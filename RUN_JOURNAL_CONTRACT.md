# Run journal (ADR 0059) — shared contract for the parallel implementation

Temporary file for the implementation agents; deleted before merge. The ADR text is at

## 1. Entry kinds / levels

`kind`: `'log' | 'trigger' | 'user-input' | 'ai' | 'message-out' | 'error'`; `level`: `'info' | 'warn' | 'error'`.

## 2. Workflow → runner: the sink (compiler emits, runner implements)

- Sink name **`falangJournal`**, one function **`append(entry)`**. Generated workflow code:
  `const { falangJournal } = proxySinks<{ falangJournal: { append(e: unknown): void } }>();`
- The compiler emits a module-level helper `__falangJournal(e)` that adds `seq` (a module-level counter, incremented
  per call — deterministic because the workflow module is isolated per execution) and `ts: Date.now()` (workflow time)
  and calls `falangJournal.append(...)`. Never awaited; wrapped in try/catch so a journal problem never fails the
  workflow.
- Sink entry shape (what `append` receives):
  `{ seq: number; ts: number; kind; level; message: string; data?: Record<string, unknown>; documentId?: string; nodeId?: string; vendor?: string }`
  — when position tracking is on, `documentId`/`nodeId` default to the top frame of the position stack unless given.
- The runner registers it in `Worker.create({ sinks: { falangJournal: { append: { fn(info, entry) {…}, callDuringReplay: false } } } })`,
  builds `sourceKey = \`${info.runId}:w:${entry.seq}\`` and pushes into the `JournalBuffer`.

## 3. Workflow → activity: node id header

- Header key **`falang-node`**, value = `defaultPayloadConverter.toPayload({ documentId, nodeId })`.
- Set by a workflow **outbound** interceptor (`scheduleActivity` and `scheduleLocalActivity`) from the position
  stack's top frame (skip when no frame). The interceptor must live in code bundled with the workflow by the backend
  (generated by the compiler next to/inside `workflows.ts` — NOT a TS file inside another package's `src/` under
  `node_modules`: Temporal's swc rule excludes `node_modules`, the cloud image installs packages there).
- The runner's activity **inbound** interceptor (`WorkerOptions.interceptors.activity`) decodes it with
  `defaultPayloadConverter.fromPayload` and runs the activity inside an `AsyncLocalStorage` the journal wrapper reads.

## 4. Activities metadata export (compiler emits, runner reads)

`activities.ts` exports, next to `__falangActivityVendors`:

```ts
export const __falangActivityJournal: Record<string, { kind: 'ai' | 'message-out'; args: string[]; result?: boolean }>;
```

key = activity function name; `args` = parameter **names**; the compiler also emits
`export const __falangActivityParams: Record<string, string[]>` (activity name → ordered parameter names parsed from
`activitySignature`) so the runner can map positional args to names. Only activities of used vendors that declare
`journal` appear in `__falangActivityJournal`; `__falangActivityParams` covers those same activities.

AI text activities return `{ text, usage?: { promptTokens, completionTokens, totalTokens }, model }` internally; the
runner journals `model`/`usage` from the result into `data` and the vendor emitter unwraps `.text`.

## 5. Runner → backend: ingest

`POST {BACKEND_INTERNAL_URL}/internal/projects/:projectId/run-journal`, header `x-internal-project-token`
(`ProjectTokenGuard`, `projectId` from the route only). Body:

```json
{
  "env": "dev" | "prod",
  "buildId": "string | null",
  "entries": [
    {
      "workflowId": "string", "runId": "string | null", "sourceKey": "string",
      "kind": "...", "level": "...", "message": "string",
      "data": { } | null, "documentId": "string | null", "nodeId": "string | null", "vendor": "string | null",
      "ts": 1759740000000
    }
  ]
}
```

≤ 500 entries per request. Response `204`. `env` from the runner's task queue (`workflow-dev-*` → `dev`, else `prod`).
Backend: text policy + size limits at ingest, `INSERT … ON CONFLICT (workflow_id, source_key) DO NOTHING`.
Source keys: workflow `'<runId>:w:<seq>'`, activity `'<runId>:a:<activityId>:<attempt>'`, buffer-loss notice
`'<runId>:lost:<n>'`, backend-side random (`'b:<uuid>'`).

## 6. Backend → client: read API (owner-scoped)

- `GET /projects/:id/runs/:workflowId/:runId/journal?after=<id>&limit=<n>` (limit default 200, max 1000)
- `GET /projects/:id/workflows/:workflowId/journal?after=<id>&limit=<n>` (all runs + `runId = null` entries)
- Response: `{ entries: IRunJournalEntryDto[], hasMore: boolean }`, ordered by `ts`, then `id` ascending;
  `after` = last seen `id` (string, bigint).
- `IRunJournalEntryDto = { id: string; workflowId; runId: string | null; env: 'dev'|'prod'; kind; level; message;
  data: Record<string, unknown> | null; documentId: string | null; nodeId: string | null; vendor: string | null;
  truncated: boolean; textsStripped: boolean; ts: string /* ISO */ }`
- Project text policy: `GET`/`PUT /projects/:id/journal-settings` → `{ storeTexts: boolean }` (owner only).
