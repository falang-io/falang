<p>
  The logic constructor allows you to create the business logic of the application.
  Then it can be exported to one of the programming languages.
</p>
<p>
  At the moment, export to the following languages is implemented: C#, C++, Rust, Go, TypeScript.
  Choose <b>Project → Export Configuration…</b> and add a target: a language and a folder, relative to the project
  folder, where its code goes. There can be several targets, each with its own folder. The configuration is saved in the
  project (<code>falang/config/logic-export.json</code>).
  <b>Project → Export Code</b> (Ctrl+Shift+E) generates the code for every target, with a progress bar and a Cancel
  button; an error in one target does not stop the others. C++, Go and C# get one source file, TypeScript and Rust one
  file per scheme.
</p>
<p>
  The editor only offers what every target language can compile: expressions use a reduced set of built-in functions
  (basic <code>Math</code>, the length and indexing of arrays and strings), so code that would fail on export is flagged
  while you type.
</p>

#### Number types

<p>
  A number variable, parameter, return value or structure field always has a kind, because the target languages need
  one. The type list offers <b>integer</b>, <b>float</b> and <b>decimal</b> instead of a plain <code>number</code>:
</p>
<ul>
  <li>
    <b>integer</b> — signed <code>int8</code>, <code>int16</code>, <code>int32</code> (the default), <code>int64</code>
    or unsigned <code>uint8</code>, <code>uint16</code>, <code>uint32</code>, <code>uint64</code>. Division of two
    integers drops the fractional part (<code>7 / 2</code> is <code>3</code>, <code>-7 / 2</code> is <code>-3</code>) in
    every language, TypeScript included, and storing a fractional value in an integer variable drops it too. Overflow is
    whatever the target language does; TypeScript does not wrap around.
  </li>
  <li><b>float</b> — <code>float32</code> or <code>float64</code> (the default).</li>
  <li>
    <b>decimal</b> — an exact fixed-point number for money and similar values: <i>digits</i> in total (up to 18) and
    <i>decimals</i> after the point. <code>0.1 + 0.2</code> is exactly <code>0.3</code>; results of multiplication and
    division, and values stored into a variable with fewer decimals, are rounded half away from zero; a decimal prints
    with all its decimals (<code>12.50</code>). Mixing a decimal with an integer gives a decimal, with a float gives a
    float. In TypeScript a decimal is an ordinary <code>number</code> (exact up to 15 significant digits).
  </li>
</ul>
<p>
  Mixing two widths gives the wider one; at the same width the unsigned one wins, and an integer mixed with a float
  gives the float. In the expression editor every kind is just <code>number</code>. A scheme saved before number kinds
  existed shows <code>number</code> as an error on the icon until you pick a kind — nothing is converted
  automatically. The <code>any</code> type and enums are not offered: no target language compiles them yet.
</p>

<p>Currently there are four types of schemes:</p>
<ul>
  <li>
    <b>Function</b>. Can accept parameters as input and call other functions.
  </li>
  <li>
    <b>Object structure</b>: description of data structures. They can be used as data types in a function.
  </li>
  <li>
    <b>Enum</b>: a named list of values. Export of enum types is not supported yet.
  </li>
  <li>
    <b>External API</b>. Description of the external API. In the code, depending on the language, objects or interfaces are generated.
    When calling any function, client code must pass the implementation of this API as a parameter.
     In the function diagram it is possible to call the API by adding the corresponding icon.
  </li>
</ul>
