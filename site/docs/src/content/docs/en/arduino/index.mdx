<p>
  Falang for Arduino is a desktop app for programming Arduino boards with flowcharts. You draw <code>setup</code> and{' '}
  <code>loop</code> as schemes, describe your wiring in the <code>Devices</code> document, and the app compiles
  everything into an ordinary Arduino sketch, uploads it to the board and lets you debug it right on the hardware.
</p>

#### What you need

<ul>
  <li>
    <a href="https://arduino.github.io/arduino-cli/" target="_blank">
      arduino-cli
    </a>{' '}
    installed — the app uses it to compile and upload, it is not bundled. The app looks for it on <code>PATH</code>, in
    the usual install locations (Homebrew on macOS, <code>Program Files\Arduino CLI</code> on Windows,{' '}
    <code>~/.local/bin</code> on Linux) and inside an installed Arduino IDE 2, which ships its own copy. To use a copy
    somewhere else, start the app with the <code>FALANG_ARDUINO_CLI</code> environment variable set to its full path. If
    it can't be found, the <b>Build &amp; Upload</b> dialog says so.
  </li>
  <li>
    The core for your board, installed once with arduino-cli: <code>arduino-cli core install arduino:avr</code> for Uno,
    Nano and Mega, <code>esp32:esp32</code> for ESP32.
  </li>
  <li>
    For the RGB strip driver only: <code>arduino-cli lib install "Adafruit NeoPixel"</code>. The other bundled drivers
    need no extra libraries.
  </li>
</ul>

#### Projects

<p>
  <b>File → New Project…</b> asks for a name, a folder and a board — Arduino Uno, Nano, Nano (old bootloader), Mega 2560
  or ESP32 Dev Module. Every project has three fixed documents: <code>setup</code>, <code>loop</code> and{' '}
  <code>Devices</code>; any other scheme you add is a helper function you can call from them. See{' '}
  <a href="./project-setup/">Project setup</a> for the board binding and the <code>Devices</code> document.
</p>

#### Icons

<p>
  A scheme offers the usual icons plus Arduino-specific ones, which are in the <b>Arduino</b> group of the insert menu
  (pins and built-in functions) and the <b>Device</b> group (actions of the devices added in <code>Devices</code>).
</p>
<ul>
  <li>
    <b>Standard icons</b> — new variable, action, function call, if, switch, loops (for each, from/to, while, cycle) and
    exits (break, continue, return). Expressions are written in a TypeScript-like syntax limited to what compiles to
    C++, with Arduino's own functions and constants available: <code>digitalRead</code>, <code>analogWrite</code>,{' '}
    <code>millis</code>, <code>map</code>, <code>constrain</code>, <code>HIGH</code>/<code>LOW</code>, <code>A0</code>…
    <code>A7</code> and so on.
  </li>
  <li>
    <b>Pins</b>: <b>Set digital pin</b> (pin number and a HIGH/LOW switch), <b>Set analog pin (PWM)</b> (a 0–255
    slider), <b>Read digital pin</b> and <b>Read analog pin</b> (each stores the reading in a new variable; for the
    analog read, the pin is the channel number, 0 for A0). Pin modes are set in the <code>Devices</code> document, not
    with an icon.
  </li>
  <li>
    <b>Built-in functions</b>: <b>Delay</b>, <b>Delay (microseconds)</b>, <b>Millis</b>, <b>Micros</b>, <b>Random</b>,{' '}
    <b>Random seed</b>, <b>Serial begin</b>, <b>Serial print</b>, <b>Serial println</b>. Their arguments are fixed
    numbers; to print a variable, write <code>Serial.println(x)</code> in an action.
  </li>
  <li>
    <b>Driver actions</b> — one icon per action of each installed driver, titled "&lt;driver&gt;: &lt;action&gt;", for
    example <b>Servo: Set angle</b>.
  </li>
</ul>
<p>
  Variables can be whole numbers and floating-point numbers of various sizes, and booleans. Strings, arrays and
  structures are not supported in Arduino projects yet, and neither are the <b>Log</b> and <b>Throw</b> icons — the
  board has no console or exceptions.
</p>

#### Bundled drivers

<ul>
  <li>
    <b>Servo</b> — <i>Set angle</i> (pin, 0–180°).
  </li>
  <li>
    <b>DHT11 / DHT22</b> — <i>Read temperature (°C)</i>, <i>Read humidity (%RH)</i>; the result is NaN if the read
    fails. Leave 1–2 seconds between reads.
  </li>
  <li>
    <b>HC-SR04</b> ultrasonic sensor — <i>Read distance (cm)</i>; −1 on timeout.
  </li>
  <li>
    <b>LCD1602 (I2C)</b> and <b>LCD1602 (Parallel)</b> — <i>Clear display</i>, <i>Print text</i> (column, row and text;
    the text can include expressions as <code>{'${…}'}</code>). Add the display in the <code>Devices</code> document so
    it is initialized at startup.
  </li>
  <li>
    <b>Addressable RGB strip (WS2812/NeoPixel)</b> — <i>Set pixel color</i> and <i>Show</i> (push the colors to the
    strip). Needs the Adafruit NeoPixel library.
  </li>
</ul>
<p>Only the drivers your sketch actually uses are copied into it.</p>

#### Your own drivers

<p>
  You can add your own device drivers — per project, or in a personal library shared by all your projects — and manage
  them from <b>Sketch → Drivers…</b>. See <a href="./drivers/">Custom device drivers</a>.
</p>

#### Build &amp; Upload

<p>
  <b>Sketch → Build &amp; Upload…</b> opens a dialog showing the project's board and a <b>Port</b> list (with{' '}
  <b>Refresh</b>):
</p>
<ul>
  <li>
    <b>Compile</b> generates the sketch and compiles it without uploading;
  </li>
  <li>
    <b>Upload</b> compiles the current schemes and uploads them to the board on the selected port;
  </li>
  <li>
    <b>Upload (debug)</b> uploads a build with tracing and starts the <a href="./debugging/">debugger</a>.
  </li>
</ul>
<p>
  The generated sketch is <code>src/sketch/sketch.ino</code> in the project folder, together with the drivers it uses;
  the folder is rewritten on every build. Errors in the schemes are listed with the document name, and an arduino-cli
  failure shows its full output in the dialog.
</p>
