<p>
  <b>Драйвер</b> учит приложение работать с датчиком, дисплеем или модулем: это пара файлов C++ и описание иконок,
  которые он добавляет. Кроме встроенных драйверов, можно написать свои — или поручить это агенту — не меняя приложение.
</p>

#### Где живут драйверы

<ul>
  <li>
    <b>Встроенные</b> — поставляются с приложением. Только для чтения.
  </li>
  <li>
    <b>Проект</b> — папка <code>falang/drivers/&lt;id&gt;/</code> внутри проекта. Она — часть проекта: попадает в
    историю версий и переезжает вместе с папкой проекта на другой компьютер.
  </li>
  <li>
    <b>Личная библиотека</b> — папка <code>drivers</code> в папке данных приложения, общая для всех ваших проектов.
  </li>
</ul>
<p>
  Если один и тот же <code>id</code> есть в нескольких местах, копия из проекта главнее библиотечной, а та — главнее
  встроенной. Когда схема или документ <code>Devices</code> используют драйвер из библиотеки или встроенный, приложение{' '}
  <b>само копирует его в проект</b> (библиотечный — при открытии проекта и перед каждой сборкой), так что проект
  продолжает собираться, даже если библиотека изменится. В скетч попадают только используемые драйверы.
</p>

#### Окно Drivers…

<p>
  <b>Sketch → Drivers…</b> показывает все драйверы с областью и статусом. Здесь можно:
</p>
<ul>
  <li>
    <b>Создать</b> драйвер проекта из небольшого шаблона, <b>загрузить</b> файл <code>.falang-driver.json</code> (весь
    драйвер в одном файле) в проект или библиотеку и <b>скачать</b> любой драйвер в таком виде, чтобы поделиться.
  </li>
  <li>
    <b>Копировать</b> драйвер между библиотекой и проектом или заменить копию в проекте версией из библиотеки.
  </li>
  <li>
    <b>Проверить</b> — формат, отсутствие конфликтов имён C-функций с другими драйверами и функциями Arduino, типизацию
    шаблона каждого действия, совместимость уже существующих в проекте иконок, а также компиляцию небольшого тестового
    скетча через arduino-cli для платы проекта. Отсутствующее ядро или библиотека — только предупреждение, не ошибка.
  </li>
  <li>
    <b>Открыть папку</b> — править файлы драйвера в своём редакторе; приложение подхватит изменения само. Драйвер,
    ставший некорректным, помечается, а <b>сборка блокируется</b>, пока проект использует некорректный драйвер, причина
    показывается.
  </li>
  <li>
    <b>Удалить</b> — отклоняется со списком мест, пока проект ещё использует драйвер.
  </li>
</ul>

#### Формат

<p>
  Драйвер — это папка с <code>driver.config.json</code> и файлами <code>.h</code>/<code>.cpp</code>, которые он
  перечисляет; то же самое в одном файле — пакет <code>.falang-driver.json</code>:{' '}
  <code>{'{ "formatVersion": 1, "config": …, "files": { "имя": "текст" } }'}</code>. Конфиг — просто данные, ничего из
  него не исполняется:
</p>
<ul>
  <li>
    <code>id</code> (kebab-case), <code>label</code>, <code>notes</code> (описание простым английским, его читают
    агенты), <code>includes</code>, <code>sourceFiles</code> и <code>declarations</code> (строки{' '}
    <code>declare function …</code>, которые сообщают редактору о ваших функциях C++ — у каждой функции должен быть
    префикс, уникальный для драйвера);
  </li>
  <li>
    <code>actions</code> — по одному на каждую понятную пользователю операцию: <code>id</code>, <code>label</code>,{' '}
    <code>notes</code>, <code>fields</code> (<code>pin</code>, <code>number</code>, <code>string</code>,{' '}
    <code>boolean</code>, <code>select</code>, <code>new-variable</code>) и <code>codeTemplate</code> с подстановками{' '}
    <code>{'${поле}'}</code>; у действия с полем <code>new-variable</code> задаётся ещё и <code>resultType</code> (
    <code>int</code>, <code>float</code>, <code>bool</code> или <code>string</code>);
  </li>
  <li>
    необязательный раздел <code>device</code> — поля и <code>setupTemplate</code>: драйвер можно добавить в документ{' '}
    <code>Devices</code>, и он будет вызван один раз в <code>setup()</code>;
  </li>
  <li>
    необязательный раздел <code>locales</code> — переводы названий драйвера, действий, полей и вариантов списков по
    языкам (например, <code>"ru"</code>); непереведённое остаётся на английском, а <code>notes</code> не переводятся.
  </li>
</ul>
<p>Нужные драйверу библиотеки Arduino автоматически не устанавливаются — поставьте их через arduino-cli.</p>

#### Агенты

<ul>
  <li>
    <a href="../ai-agent/">ИИ-агент</a> в приложении умеет смотреть, создавать и править драйверы проекта, если
    попросить его добавить поддержку устройства; перед сохранением он проверяет драйвер. Если у драйвера есть раздел{' '}
    <code>device</code>, агент также добавляет его экземпляр в документ <code>Devices</code> (<code>get_devices</code> /{' '}
    <code>set_devices</code>).
  </li>
  <li>
    <a href="../coding-agents/">Кодинг-агент</a>, подключённый по MCP, получает в Arduino-проекте инструменты для
    драйверов: <code>list_drivers</code>, <code>get_driver</code>, <code>validate_driver</code>, <code>set_driver</code>
    , <code>delete_driver</code> и <code>use_library_driver</code>, а также <code>get_devices</code> и{' '}
    <code>set_devices</code> для добавления экземпляров драйверов и выводов в документ <code>Devices</code>. Новые
    иконки драйверов ему доступны сразу, а драйверы, созданные в приложении, появляются без перезапуска агента.
  </li>
</ul>
