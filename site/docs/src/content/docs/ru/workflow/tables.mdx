<p>
  <b>Таблица</b> — место внутри проекта, где сценарии помнят что-то между запусками: пользователей, которых видел бот,
  список лидов, счётчик, очередь заказов на повтор. Ни учётных данных, ни строки подключения, ни SQL: вы создаёте
  таблицу рядом с функциями, задаёте типизированные поля и используете её в узлах. Для внешней базы данных
  есть <a href="../databases/">Базы данных</a>.
</p>

#### Таблицы и поля

<p>
  Таблицы лежат в разделе <b>Tables</b> дерева проекта. Откройте таблицу, чтобы изменить поля: у каждого есть имя и тип —{' '}
  <code>text</code>, <code>number</code>, <code>boolean</code>, <code>date</code>, <code>datetime</code> (хранится в
  UTC, показывается в вашем часовом поясе), <code>select</code> (фиксированный список вариантов), <code>json</code> и{' '}
  <code>file</code>. Имя поля может быть на любом языке, уникально в таблице (без учёта регистра) и не может быть{' '}
  <code>id</code>, <code>version</code>, <code>createdAt</code>, <code>updatedAt</code>, <code>and</code> или{' '}
  <code>or</code> — эти зарезервированы. У каждой записи есть системные поля: <code>id</code>, <code>version</code>,{' '}
  <code>createdAt</code>, <code>updatedAt</code>.
</p>

<p>
  Схема (таблицы и поля) — часть проекта: она экспортируется, попадает в версии и общая для тестового стенда и прода.
  <b>Записи</b> — нет: у стенда и прода они свои, поэтому тестовые запуски не трогают боевые данные. Записи никогда
  не входят в экспорт проекта и в версии. Восстановление версии, которая старше таблицы, удаляет таблицу вместе с
  записями.
</p>

#### Таблица данных

<p>
  Редактор таблицы — это сетка с переключателем <b>dev / prod</b>. Записи листаются (по 50 на страницу), ищутся (по
  текстовым полям и select), сортируются и правятся прямо в ячейках. У каждой записи есть история: можно посмотреть
  прежние значения и восстановить одно из них. Ещё доступны:
</p>

<ul>
  <li><b>Импорт CSV</b> (до 5 МБ) — добавить к записям или заменить их; недостающие поля создаются по заголовку.</li>
  <li><b>Экспорт CSV</b> выбранного окружения.</li>
  <li><b>Очистить</b> все записи окружения.</li>
  <li><b>Скопировать dev в prod</b> — заменяет боевые записи тестовыми.</li>
  <li>Загрузка файлов в ячейки <code>file</code>; скачивать их могут владелец проекта и редакторы.</li>
</ul>

#### Узлы

<p>С таблицей работают пять узлов; таблицу выбирают в самом узле, а редактор сам подставляет типы строк и полей:</p>

<ul>
  <li><b>Select</b> — возвращает подходящие записи массивом (<code>where</code>, <code>orderBy</code>, <code>limit</code>, по умолчанию 100, максимум 1000).</li>
  <li><b>Get</b> — возвращает одну запись.</li>
  <li><b>Insert</b> — добавляет запись и возвращает её с <code>id</code>. Вставка безопасна при автоматических повторах: один и тот же шаг не создаст запись дважды.</li>
  <li><b>Update</b> — меняет все записи, подходящие под <code>where</code>, и возвращает их число.</li>
  <li><b>Delete</b> — удаляет подходящие записи и возвращает их число.</li>
</ul>

<p>
  <code>where</code> задаётся по именам полей и работает как в <a href="../databases/">Базах данных</a>: простое значение
  означает «равно», объект принимает операторы (<code>eq</code>, <code>ne</code>, <code>gt</code>, <code>gte</code>,{' '}
  <code>lt</code>, <code>lte</code>, <code>in</code>, <code>notIn</code>, <code>isNull</code>, <code>contains</code>, …),
  а массивы <code>and</code>/<code>or</code> объединяют условия. Update и Delete требуют непустой <code>where</code>.{' '}
  <code>orderBy</code> — обычный текст:
</p>

```ts
// where
{ status: { in: ['new', 'paid'] }, total: { gt: 100 } }

// orderBy
'priority asc, createdAt desc'
```

<p>
  <b>Оптимистичная блокировка.</b> Каждое изменение увеличивает <code>version</code> записи. Укажите в{' '}
  <code>where</code> и <code>id</code>, и <code>version</code> — запись изменится, только если с момента чтения её никто
  не трогал. Ноль изменённых записей значит, что кто-то успел раньше; сценарий сам решает, перечитать и повторить или
  остановиться:
</p>

```ts
// where узла Update
{ id: order.id, version: order.version }
// patch
{ status: 'paid' }
```

<p>
  В редакторе узлы ссылаются на поля по именам, но опубликованная версия несёт идентификаторы полей: переименование
  поля никогда не ломает уже работающую версию. Удалённое поле приведёт к ошибке{' '}
  <code>field "x" no longer exists</code>; если сменить тип поля, значения, которые больше не разбираются, читаются как
  пустые.
</p>

#### Триггеры

<p>
  Три триггера запускают сценарий, когда запись выбранной таблицы <b>создана</b>, <b>изменена</b> или <b>удалена</b>.
  Таблицу выбирают в «Новом триггере». Сценарий получает <code>event</code>:{' '}
  <code>{'{ table, record, previous?, changedFields?, source }'}</code> — запись по именам полей, прежние значения для
  изменения и удаления, имена изменённых полей для изменения.
</p>

<ul>
  <li>Триггеры срабатывают только на изменения, сделанные сценариями (<code>source</code> равен <code>"workflow"</code>). Правки в таблице, импорт CSV, «Очистить» и «Скопировать dev в prod» их не запускают.</li>
  <li>Окружение следует за записью: запуск на стенде будит триггеры стенда, боевой — боевые.</li>
  <li>Каждое изменение запускает отдельный запуск. Доставляется не более 600 событий в минуту на таблицу и окружение, остальное попадает в журнал запусков.</li>
  <li>Если стенд не был активен 10 минут, ожидающее событие отбрасывается, а не доставляется с опозданием.</li>
  <li>Триггер, который пишет в свою же таблицу, срабатывает снова — так задумано. Защититесь от цикла проверкой <code>event.source</code> или <code>event.changedFields</code>.</li>
  <li>«Запустить функцию» у триггера просит тестовый <code>event</code> с ключами по именам полей.</li>
</ul>

#### Лимиты и доступ

<p>
  На проект: 20 таблиц, 100 полей в таблице, 10 000 записей на таблицу и окружение, 64 КБ на запись. Администратор
  меняет их для пользователя в окне <b>Limits</b> (см. <a href="../administration/">Администрирование</a>).
</p>

<p>
  Владелец и редакторы могут всё перечисленное. <b>Исполнитель</b> (см. <a href="../project-users/">Пользователи
  проекта</a>) и администратор платформы видят вкладку Tables только для чтения. Гость, смотрящий шаблон, видит только
  поля таблиц.
</p>

#### ИИ-агент

<p>
  <a href="../ai-agent/">Агент</a> создаёт таблицы, правит их поля (файлом <code>tables/&lt;имя&gt;.json</code> или
  инструментом) и использует их в функциях. Читать и править записи он в этой версии не умеет — для данных есть таблица
  и CSV.
</p>
