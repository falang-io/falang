<p>
  Некоторые API недоступны из региона, где работает ваше развёртывание Falang, — например Telegram или OpenAI из России
  либо российские маркетплейсы из-за рубежа. Не нужно переносить всё развёртывание: администратор запускает небольшой
  прокси там, откуда эти API доступны, и указывает, какие интеграции должны им пользоваться. Остальной трафик идёт
  напрямую, как и раньше.
</p>

#### Запуск прокси

<p>
  Прокси — отдельный сервис <code>falang-proxy</code> из папки <code>proxy/</code> репозитория (Node 24, без
  зависимостей). Соберите и запустите его на хосте в нужном регионе:
</p>

```sh
cd proxy
docker build -t falang-proxy .
docker run -d --restart unless-stopped \
  -e PROXY_TOKENS=длинный-случайный-секрет \
  -p 8080:8080 falang-proxy
```

      <th>Переменная</th>

    </tr>

<p>
  Проверить, что сервис жив, можно командой <code>curl http://your-proxy:8080/health</code> — он отвечает{' '}
  <code>200 ok</code> без авторизации.
</p>
<p>
  <b>Берегите токен.</b> Falang передаёт токен в заголовке <code>Proxy-Authorization</code> каждого запроса к прокси.
  Поставьте перед прокси HTTPS-терминацию (обратный прокси, а в Falang укажите адрес с <code>https://</code>) или
  держите его в частной сети. Трафик, который <i>проходит через туннель</i> к HTTPS-API, остаётся зашифрованным
  end-to-end: прокси видит только хост и порт, но не содержимое запросов.
</p>

#### Настройка в админ-приложении

<ol>
  <li>
    Откройте админ-приложение и перейдите на страницу <b>Proxy</b>.
  </li>
  <li>
    Введите <b>URL</b> прокси (<code>http://…</code> или <code>https://…</code>) и <b>токен</b>. Если настройки уже
    сохранены, оставьте поле токена пустым — сохранённый токен не изменится.
  </li>
  <li>
    В поле <b>Integrations</b> выберите вендоров, трафик которых нужно пустить через прокси. Список можно искать, он
    разделён на встроенные интеграции и модули ActivePieces.
  </li>
  <li>
    Нажмите <b>Save</b>. <b>Reset</b> удаляет URL, токен и выбор — весь трафик снова идёт напрямую.
  </li>
</ol>

#### Что идёт через прокси

<p>
  Маршрутизируется только трафик <b>выбранных</b> интеграций; решение принимается для каждого запроса отдельно:
</p>
<ul>
  <li>действия, вопросы и выборы этих интеграций, выполняемые в раннере workflow;</li>
  <li>
    работа бэкенда для них: long polling и настройка вебхука Telegram, обработчики входящих вебхуков, загрузка вариантов
    выпадающих полей, «Sync structure» и обмен OAuth2-токена;
  </li>
  <li>выбранные модули ActivePieces (действия, опрос триггеров, загрузка вариантов).</li>
</ul>
<p>
  Что через прокси <b>не</b> идёт:
</p>
<ul>
  <li>
    интеграции с базами данных (PostgreSQL, MySQL) — их соединения это обычный TCP, а не HTTP, поэтому выбор таких
    интеграций ни на что не влияет;
  </li>
  <li>внутренние вызовы Falang (бэкенд, файловое хранилище, сервисы media и ActivePieces);</li>
  <li>сам чат ИИ-агента — у него собственные настройки адреса;</li>
  <li>
    модули ActivePieces, которые создают собственный HTTP-агент или открывают «сырые» TCP-соединения (SMTP, IMAP,
    MongoDB и подобные).
  </li>
</ul>

#### Когда изменения вступают в силу

<ul>
  <li>Бэкенд — примерно за 15 секунд.</li>
  <li>Поды раннеров запущенных workflow — примерно за 30 секунд, пересборка и перезапуск не нужны.</li>
  <li>Сервис ActivePieces — примерно за 30 секунд.</li>
</ul>

#### Если что-то не работает

<ul>
  <li>
    <b>407 Proxy Authentication Required</b> — токен в админ-приложении не совпадает ни с одним значением{' '}
    <code>PROXY_TOKENS</code> на прокси.
  </li>
  <li>
    <b>403 Forbidden</b> — прокси не разрешил порт назначения. Если API вендора работает на нестандартном порту,
    добавьте его в <code>PROXY_ALLOWED_PORTS</code> (или укажите <code>*</code>).
  </li>
  <li>
    Отказ в соединении или таймаут — прокси недоступен из развёртывания; проверьте <code>/health</code> с хоста бэкенда
    и файрволы по пути.
  </li>
  <li>
    Вызов по-прежнему не проходит — убедитесь, что вендор отмечен на странице Proxy; журнал самого прокси (одна строка
    на запрос, без токена) покажет, дошёл ли запрос.
  </li>
</ul>
