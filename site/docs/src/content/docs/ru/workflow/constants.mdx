<p>
  В каждом проекте рядом с <b>Integrations</b> есть закреплённый документ <b>Constants</b> — таблица именованных
  значений: адрес сайта, id чата, цена, лимит, флаг функции — всё, что отличается на тестовом стенде и в продакшене или
  что хочется менять, не правя схему.
</p>

#### Таблица

<p>У каждой константы четыре колонки:</p>

<ul>
  <li>
    <b>Название</b> — заглавные латинские буквы, цифры и подчёркивание, начинается с буквы: <code>API_URL</code>,
    <code>MAX_RETRIES</code>, <code>SUPPORT_CHAT_ID</code>. Названия в проекте не повторяются.
  </li>
  <li>
    <b>Тип</b> — <i>Строка</i>, <i>Число</i> или <i>Логическое</i>.
  </li>
  <li>
    <b>dev</b> — значение для тестового стенда (запуск, Run, отладка).
  </li>
  <li>
    <b>prod</b> — значение для опубликованных версий.
  </li>
</ul>

<p>Откройте документ в дереве проекта, нажмите <b>+ Добавить константу</b>, заполните форму и сохраните.</p>

#### Как использовать

<p>
  Константа доступна по имени в любом поле кода проекта — действиях, условиях, текстах сообщений, полях интеграций — без
  импорта. Редактор знает её тип, поэтому работают подсказки и проверка ошибок:
</p>

```ts
// текст сообщения
Заказ принят, отслеживайте его на ${SITE_URL}/orders/${orderId}
// условие
attempts < MAX_RETRIES
// действие
discount = VIP_DISCOUNT_ENABLED ? price * 0.9 : price
```

<p>Константы только для чтения: присвоить им значение нельзя.</p>

#### Когда изменение вступает в силу

<p>
  Значения записываются в сборку: тестовый стенд получает значения <b>dev</b> при запуске, версия — значения
  <b>prod</b> при публикации. После изменения константы перезапустите тестовый стенд или опубликуйте новую версию. Уже
  опубликованные версии сохраняют значения, с которыми были собраны, поэтому откат на старую версию возвращает и её
  константы.
</p>

#### Константы и агенты

<p>
  Встроенный ИИ-агент видит константы проекта и может сам создавать, менять и удалять их — например, если попросить его
  «вынести id чата поддержки в настройку». Агентам, подключённым по MCP, доступны те же два инструмента:
  <code>list_constants</code> и <code>set_constants</code>.
</p>

#### Для чего константы не подходят

<p>
  Константы хранятся как обычные данные проекта: их видят все, у кого есть доступ к проекту, они попадают в историю
  версий и в экспорт проекта. Пароли, токены и ключи API храните в <a href="../integrations/">учётных данных
  интеграций</a> — они шифруются и не экспортируются.
</p>
