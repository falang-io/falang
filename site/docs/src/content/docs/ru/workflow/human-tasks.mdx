<p>
  Узел <b>«Задача для человека»</b> ставит сценарий на паузу и ждёт, пока человек примет решение — одобрить или
  отклонить счёт, подтвердить возврат средств, выбрать один из нескольких вариантов, — а затем продолжает по ветке,
  соответствующей выбору, с собственным ответом резолвера доступным внутри этой ветки как типизированное значение. Это
  тот же приём, что и вопрос в Telegram (отправить, подождать, разветвиться по нажатой кнопке), только без мессенджера —
  «сообщением» становится строка на странице внутри самого продукта.
</p>

#### Поля

<ul>
  <li>
    <b>Заголовок</b> и <b>Описание</b> — короткая сводка, показываемая в списке задач, и более длинное, оформленное в
    Markdown объяснение (что нужно решить, ссылки, суммы), показываемое на самой задаче.
  </li>
  <li>
    <b>Контекст</b> — необязательное выражение, вычисляющее любое структурированное значение (заказ, который
    согласовывается, запись, которую проверяют), показывается на задаче как блок только для чтения — никогда не
    редактируется тем, кто её решает.
  </li>
  <li>
    <b>Вложения</b> — необязательный список <a href="./files/">файлов</a>, показывается как ссылки для скачивания.
  </li>
  <li>
    <b>Таймаут</b> — необязательная длительность (<code>48h</code>, <code>3d</code>). Оставьте пустым — сценарий будет
    ждать вечно; задайте — и узел возьмёт фиксированную автоматическую ветку <b>«Таймаут»</b>, если никто не решит
    задачу вовремя (см. ниже).
  </li>
</ul>

#### Опции и типизированные ответы

<p>
  Каждая опция — это кнопка, которую видит человек на задаче — по умолчанию <b>«Одобрить»</b>/<b>«Отклонить»</b>,
  свободно переименовываемые или дополняемые, точно как кнопки вопроса в Telegram. Что делает опции задачи для человека
  отличными от обычной ветки — то, что каждая может ещё и собрать типизированное значение от того, кто её решает:
</p>

<ul>
  <li>
    <b>Void</b> — обычная кнопка, заполнять больше нечего.
  </li>
  <li>
    <b>Текст</b> — текстовое поле (причина отказа, исправленное значение).
  </li>
  <li>
    <b>Число</b> — числовое поле ввода.
  </li>
  <li>
    <b>Булево</b> — чекбокс/переключатель.
  </li>
</ul>

<p>
  Отдельного поля «комментарий» нет: опция <b>«Отклонить»</b> с ответом типа <b>Текст</b> и подсказкой «Причина» —{' '}
  <i>и есть</i> поле для комментария. Внутри ветки каждой опции доступны две переменные: <code>task</code> (кто и когда
  решил задачу) и, для любой опции кроме <b>Void</b>, <code>data</code> — типизированная точно так, как задан тип ответа
  этой опции.
</p>

#### Ветка по таймауту

<p>
  Заданный <b>Таймаут</b> автоматически добавляет к узлу ещё одну ветку — фиксированную, всегда последнюю, её нельзя
  удалить или переименовать. Если никто не решит задачу за отведённое время, сценарий пойдёт по этой ветке (сама задача
  при этом помечается на странице Tasks как <b>«Истекла»</b>) — удобно для сценариев вида «эскалировать, если никто не
  ответил за день». Сценарий, остановленный или пересобранный, пока задача ещё открыта, тоже закрывает её (как{' '}
  <b>«Отменена»</b>) — задача никогда не остаётся висеть открытой, указывая на запуск, которого уже не существует.
</p>

#### Страница Tasks

<p>
  Все открытые (и прошлые) задачи живут на странице <b>Tasks</b> — рядом со страницей Runs, доступной из списка
  проектов, а также, отфильтрованной под конкретный сценарий, из вкладки <b>Tasks</b> внутри редактора. Задача видна
  только <b>владельцу проекта</b>, который её создал, — в этой версии нет ни списка исполнителей, ни внешней ссылки, ни
  доступа администратора: владелец проекта — тот, кто строит и тестирует сценарий, поэтому именно он решает и то, чего
  сценарий ждёт. Открытие задачи показывает описание, контекст, вложения и по одной кнопке на каждую опцию — с
  типизированным полем ввода рядом, если опция собирает значение.
</p>

#### Dev и production

<p>
  Задача, созданная во время разработки сценария (dev-запуск), — тоже настоящая строка, решаемая с той же страницы
  Tasks: именно так тестируется сценарий с согласованием — соберите его, запустите и одобрите/отклоните сами со вкладки
  Tasks рабочего пространства. Production-задача переживает повторное развёртывание, поскольку опубликованный запуск
  продолжает выполняться на своей закреплённой версии независимо от того, что публикуется дальше; решение задачи
  достигает именно этого запуска.
</p>

#### Вопросы в Telegram тоже умеют истекать

<p>
  Узел вопроса <a href="./integrations/">Telegram</a> в этом же проходе получил такое же поле <b>«Таймаут»</b> — задайте
  его, и вопрос с inline-клавиатурой, оставшийся без ответа, пойдёт по собственной автоматической ветке таймаута: кнопки
  убираются, и вместо бесконечного ожидания отправляется короткое сообщение «этот вопрос устарел».
</p>
