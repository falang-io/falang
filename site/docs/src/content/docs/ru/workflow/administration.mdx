<p>
  У развёртывания workflow-движка есть одна поверхность для оператора помимо самого редактора — админ-приложение. В нём
  оператор управляет тем, кто ещё может администрировать развёртывание, и включает OAuth2-интеграции из каталога
  ActivePieces.
</p>

#### Роли

<p>
  По умолчанию каждая учётная запись — обычный <b>пользователь</b> (<code>user</code>). Учётная запись с ролью
  <b>админ</b> (<code>admin</code>) дополнительно может открыть админ-приложение и всё описанное ниже — тот же логин, та
  же сессия, отдельных учётных данных не требуется.
</p>
<ul>
  <li>
    Админ может повысить любого другого пользователя до админа или понизить админа обратно до пользователя — на странице
    «Пользователи».
  </li>
  <li>Админ не может изменить собственную роль — это защищает развёртывание от случайной потери админ-доступа.</li>
  <li>
    Изменение роли вступает в силу немедленно — повторный вход не нужен, достаточно обновить страницу у затронутой
    учётной записи.
  </li>
</ul>

#### Первый админ

<p>
  На локальном или self-hosted стенде с сидом по умолчанию встроенная учётная запись <code>admin</code>/
  <code>admin</code>
  уже является админом — настраивать ничего не нужно.
</p>
<p>
  На развёртывании с самостоятельной регистрацией (хостинговый продукт) сначала зарегистрируйтесь обычным образом, а
  затем сделайте эту учётную запись админом одним из двух способов:
</p>
<ul>
  <li>
    Укажите имя пользователя в настройке бэкенда <code>ADMIN_USERNAMES</code> (через запятую, если пользователей
    несколько) и один раз перезапустите бэкенд — все перечисленные пользователи будут повышены при старте.
  </li>
  <li>
    Либо задайте роль напрямую в базе данных:
    <pre>
      <code>UPDATE users SET role = 'admin' WHERE username = '…';</code>
    </pre>
  </li>
</ul>
<p>Для всех последующих админов ни один из этих шагов не нужен — просто повысьте их со страницы «Пользователи».</p>

#### Управление пользователями

<p>
  Self-hosted развёртывание по умолчанию не позволяет посторонним регистрироваться самим. Учётные записи создаёт админ:
</p>
<ul>
  <li>
    <b>Создать пользователя</b> — на странице «Пользователи» нажмите «Создать пользователя», введите имя и подтвердите.
    Будет сгенерирован случайный пароль, который показывается <b>один раз</b> в окне (с кнопкой «Копировать») —
    передайте его человеку. В читаемом виде он нигде не хранится и повторно показан быть не может.
  </li>
  <li>
    <b>Сбросить пароль</b> — нажмите «Сбросить пароль» в строке пользователя и подтвердите. Старый пароль сразу
    перестаёт работать, а новый сгенерированный показывается один раз так же, как выше. Почты нет: забытые пароли всегда
    сбрасывает админ.
  </li>
  <li>
    <b>Сменить свой пароль</b> — любой вошедший пользователь может нажать «Сменить пароль» (в шапке списка проектов и в
    шапке админ-приложения) и ввести текущий пароль и новый, не короче 8 символов.
  </li>
</ul>
<p>
  <b>Предупреждение о пароле по умолчанию.</b> Свежая установка создаёт учётную запись <code>admin</code>/
  <code>admin</code>. Пока у неё остаётся пароль <code>admin</code>, на списке проектов и на каждой странице
  админ-приложения показывается предупреждающая плашка с кнопкой «Сменить пароль»; после смены пароля она пропадает.
  Смените пароль до того, как открывать инстанс в интернет.
</p>
<p>Публичной регистрацией управляют две настройки бэкенда:</p>
<ul>
  <li>
    <code>SELF_SERVICE_SIGNUP</code> — по умолчанию <code>false</code>. При <code>false</code> эндпоинт регистрации
    отвечает <code>403</code>, а на странице входа нет ссылки «Создать аккаунт». Поставьте <code>true</code>, чтобы
    разрешить регистрацию всем (хостинговый продукт и локальный Docker Compose-стенд так и настроены).
  </li>
  <li>
    <code>TERMS_URL</code> — необязательная. Если задана, форма регистрации показывает обязательную галочку «Я принимаю
    условия» со ссылкой на этот адрес, бэкенд отклоняет регистрацию без согласия, а время согласия записывается в
    учётную запись.
  </li>
</ul>

#### Админ-приложение

<p>
  Откройте <code>/admin</code> на том же хосте, что и редактор workflow (у вошедшего админа также появляется ссылка
  «Admin» на странице списка проектов). В нём три страницы:
</p>
<ul>
  <li>
    <b>Пользователи</b> — список всех учётных записей с переключателем роли в каждой строке.
  </li>
  <li>
    <b>OAuth-учётные данные</b> — OAuth2-клиенты, настроенные для интеграций ActivePieces, см. ниже.
  </li>
  <li>
    <b>ИИ-агент</b> — настройка ИИ-агента редактирования на уровне всего развёртывания, см. ниже.
  </li>
</ul>

#### Лимиты пользователя

<p>
  Кнопка <b>Лимиты</b> в строке пользователя открывает квоты этого аккаунта: максимальный размер одного файла,
  максимальный суммарный размер файлов проекта, сроки хранения файлов и максимальное число{' '}
  <b>одновременно запущенных опубликованных версий</b> на проект (по умолчанию 3 или значение настройки развёртывания{' '}
  <code>MAX_CONCURRENT_PROD_VERSIONS</code>). Пустое поле означает «использовать значение по умолчанию»; заполненное
  переопределяет его только для проектов этого аккаунта.
</p>

#### OAuth-учётные данные — включение OAuth2-интеграций

<p>
  Интеграции из <a href="./integrations/">каталога ActivePieces</a>, которые авторизуются через OAuth2 — Google Sheets,
  Gmail, Google Drive, Slack и другие, — используют <b>один OAuth2-клиент на интеграцию, принадлежащий развёртыванию</b>
  , который настраивается здесь один раз. Пользователи никогда сами не вводят client ID/secret — им достаточно нажать
  «Connect».
</p>
<p>
  Интеграция без настроенного клиента <b>отключена</b>: она вообще не появляется ни в «добавить интеграцию», ни в пикере
  действий редактора.
</p>
<p>Чтобы включить интеграцию:</p>
<ol>
  <li>
    Откройте «OAuth-учётные данные» в админ-приложении и найдите нужную интеграцию — у неё будет статус «Disabled».
  </li>
  <li>Нажмите «Configure».</li>
  <li>Вставьте Client ID и Client secret, выданные вендором.</li>
  <li>Сохраните. Статус сменится на «Enabled», и интеграция станет доступна во всех проектах.</li>
</ol>
<p>
  Удаление настроенных учётных данных снова отключает интеграцию — существующие подключения этого вендора перестают
  подключаться и обновлять токен.
</p>

<p>
  <b>Пример для Google:</b>
</p>
<ol>
  <li>
    В{' '}
    <a href="https://console.cloud.google.com/" target="_blank">
      Google Cloud Console
    </a>{' '}
    создайте OAuth 2.0 Client ID типа «Web application».
  </li>
  <li>
    Добавьте авторизованный redirect URI вида{' '}
    <code>https://&lt;хост вашего бэкенда&gt;/oauth2/callback/&lt;id интеграции&gt;</code>. Id интеграции показан в
    колонке «Vendor» таблицы OAuth-учётных данных — для Google Sheets это
    <code>activepieces-google-sheets</code>. Для хостингового продукта хост бэкенда —{' '}
    <code>api.workflow.falang.ru</code>, поэтому redirect URI будет{' '}
    <code>https://api.workflow.falang.ru/oauth2/callback/activepieces-google-sheets</code>.
  </li>
  <li>
    Один OAuth-клиент Google Cloud может нести несколько redirect URI — добавляйте по одному на каждую включаемую
    Google-интеграцию (Gmail, Google Drive, Google Calendar, Google Forms, …), а не создавайте отдельный клиент для
    каждой.
  </li>
  <li>Вставьте Client ID и Client secret этого клиента в админ-приложение, как описано выше.</li>
</ol>

#### Что видит пользователь

<p>
  После включения интеграция появляется в списке вендоров редактора интеграций проекта наравне с остальными. Её форма
  учётных данных запрашивает только имя (плюс любые несекретные поля, специфичные для вендора) и кнопку «Connect»,
  которая открывает всплывающее окно согласия самого вендора — никаких полей client ID/secret.
</p>

<p>
  Встроенные (не из каталога) OAuth2-интеграции, такие как amoCRM и Диадок, это не затрагивает — они по-прежнему
  используют собственные поля client ID/secret, вводимые в каждой учётной записи отдельно.
</p>

#### ИИ-агент

<p>
  ИИ-агенту редактора (редактирование функции естественным языком — кнопка <b>Агент</b> на панели инструментов открывает
  его панель в правой боковой панели, рядом с кнопкой <b>История</b>; одновременно показывается только одна из двух
  панелей) для работы нужен один OpenAI-совместимый эндпоинт на уровне всего развёртывания. Настраивать его для каждого
  проекта не нужно — админ задаёт его один раз для всего развёртывания на странице «ИИ-агент»:
</p>
<p>
  Агент не ограничен тем документом, который сейчас открыт, — он может читать и редактировать другие документы проекта,
  а также создавать новые документы типа «функция» или «триггер» и структуры объектов (интерфейсы, описывающие форму
  данных, — только типы, а не хранилище). Он работает даже в совсем новом проекте без единого документа: достаточно
  описать, что нужно построить, и агент сам создаст нужные документы по ходу работы.
</p>
<ul>
  <li>
    <b>Base URL</b> — корневой адрес OpenAI-совместимого API вендора, например <code>https://api.openai.com/v1</code>{' '}
    или любой совместимый провайдер.
  </li>
  <li>
    <b>Модель</b> — название модели простым текстом, например <code>gpt-4o-mini</code>.
  </li>
  <li>
    <b>API-ключ</b> — API-ключ вендора; хранится в зашифрованном виде с помощью <code>CREDENTIALS_ENCRYPTION_KEY</code>{' '}
    развёртывания.
  </li>
</ul>
<p>
  Пока это не настроено, панель чата агента у каждого пользователя показывает уведомление «не настроено, обратитесь к
  администратору» вместо кнопки отправки — агентом просто нельзя пользоваться. При последующем редактировании настроек
  поле API-ключа специально оставляют пустым: сохранение с пустым полем оставляет текущий сохранённый ключ, меняются
  только Base URL/модель. «Reset» удаляет все три значения и снова отключает агента для всех.
</p>
<p>
  Это отдельная сущность от учётных данных интеграции «OpenAI» на уровне проекта, которые используют узлы{' '}
  <code>call-ai-text</code>/<code>call-ai-choice</code> внутри workflow — эти учётные данные не затрагиваются и
  по-прежнему настраиваются для каждого проекта отдельно, как и любая другая интеграция.
</p>
