<p>
  Интеграции OpenAI обычно нужны свой адрес и API-ключ. Если администратор вашей установки настроил{' '}
  <b>встроенный ИИ-провайдер</b>, интеграция OpenAI может работать через него: достаточно включить один
  переключатель, адрес и ключ вводить не нужно. Узлы, скомпилированные сценарии и журнал запусков не меняются —
  меняется только то, куда уходит запрос.
</p>

#### Пользователю

<ol>
  <li>
    Откройте <b>Интеграции</b>, добавьте (или откройте) интеграцию <b>OpenAI</b> и включите переключатель{' '}
    <b>Встроенный провайдер</b>. Поля адреса и API-ключа скроются — они не нужны ни для dev, ни для prod.
  </li>
  <li>
    Используйте интеграцию в любом узле OpenAI как обычно — <b>Вызов AI (текст)</b>, <b>Вопрос AI (выбор)</b>,{' '}
    <b>Вызов AI (генерация изображения)</b> и <b>Вызов AI (расшифровка аудио)</b>. В списке моделей каждого узла — модели нужного
    типа, которые сделал доступными администратор: чат-модели для текста и выбора, модели изображений для генерации
    картинок, модели распознавания речи для распознавания.
  </li>
</ol>

<p>
  Если выключить переключатель, поля адреса и ключа вернутся с тем, что было введено раньше, — переход между своим
  ключом и встроенным провайдером занимает один клик. Встроенный ИИ-агент тоже знает о провайдере: если попросить его
  сделать что-то с ИИ и не дать ключ, он создаст интеграцию через встроенный провайдер.
</p>

#### Полезно знать

<ul>
  <li>
    Узел может использовать только тот тип моделей, который предлагает администратор: если, например, в списке нет
    моделей изображений, узлу генерации картинок выбрать нечего — для него нужна интеграция со своим ключом.
  </li>
  <li>
    Потоковые ответы через встроенный провайдер недоступны (каждый вызов должен сообщать расход); узлы и так их не
    используют.
  </li>
  <li>
    Использовать можно только модели из списка администратора. Если модель позже убрать из списка, узел по-прежнему
    компилируется, но вызов падает при запуске, и ошибка видна в журнале запусков.
  </li>
  <li>
    Настройка переносится вместе с проектом: экспорт её сохраняет (секретов в ней нет). На установке без встроенного
    провайдера интеграция показывает предупреждение, а её вызовы падают, пока вы не вернётесь к своему ключу.
  </li>
  <li>
    Запросы выполняет сервер с ключом администратора; сценарий этот ключ не видит. В облачной версии вызовы могут
    списываться с баланса владельца проекта.
  </li>
</ul>

#### Администратору

<p>
  Провайдер настраивается на странице <b>Встроенный провайдер</b> админки:
</p>

<ul>
  <li>
    <b>Base URL</b> и <b>API-ключ</b> любого OpenAI-совместимого адреса (сам OpenAI, шлюз вроде OpenRouter, локальный
    сервер). Ключ хранится в зашифрованном виде и больше не показывается; чтобы оставить его прежним, оставьте поле
    пустым.
  </li>
  <li>
    <b>Модели</b> — единственные модели, которые смогут выбрать пользователи. У каждой есть ID (как его ждёт
    провайдер), необязательное название для пользователей и тип: <b>Чат</b> (действия «текст» и «выбор»),{' '}
    <b>Изображения</b> (генерация картинок, например <code>gpt-image-1</code>) или <b>Распознавание речи</b> (например{' '}
    <code>whisper-1</code>, <code>gpt-4o-mini-transcribe</code>). Кнопка <b>Загрузить у провайдера</b> читает список
    моделей самого провайдера, чтобы выбирать ID, а не вводить их вручную.
  </li>
</ul>

<p>
  Провайдер считается настроенным, когда сохранены адрес, ключ и хотя бы одна чат-модель; только тогда пользователи
  видят переключатель. Запросы идут через <a href="../integration-proxy/">прокси</a>, если он настроен для
  интеграции OpenAI. Кнопка <b>Сбросить</b> удаляет всю настройку.
</p>
