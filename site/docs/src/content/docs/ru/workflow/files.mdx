<p>
  <b>File</b> — это небольшое значение-ссылка: <code>id</code>, <code>name</code>, <code>size</code>, <code>mime</code>{' '}
  и необязательный <code>publicUrl</code> — но никогда не сами байты. Байты хранятся в собственном объектном хранилище
  платформы; сценарий передаёт между узлами только ссылку, точно так же, как передаёт число или строку. Это не даёт
  работе с файлами раздувать историю выполнения сценария, которая должна оставаться небольшой — вложение на 50&nbsp;МБ
  никогда не поместилось бы туда как значение, а его ссылка <code>File</code> помещается без проблем.
</p>

#### Откуда берётся File

<ul>
  <li>
    <b>Медиа из Telegram.</b> Фото, документ, голосовое сообщение, аудио или видео, приложенные к входящему сообщению,
    автоматически превращаются в <code>File</code> ещё до старта сценария — <code>message.photo</code>,{' '}
    <code>message.document</code>, <code>message.voice</code>, <code>message.audio</code> и <code>message.video</code>{' '}
    уже являются значениями <code>File</code> (или отсутствуют, если в сообщении нет медиа этого вида). Отдельный узел
    для «скачивания» не нужен.
  </li>
  <li>
    <b>Действие «Скачать файл».</b> Загружает содержимое по любому URL и сохраняет его как <code>File</code> — здесь
    обычная ссылка превращается в файл, с которым может работать сценарий.
  </li>
  <li>
    <b>Действие «Вызвать AI (изображение)».</b> Просит модель, совместимую с OpenAI, сгенерировать изображение по
    текстовому описанию и возвращает его как <code>File</code>.
  </li>
  <li>
    <b>HTTP-запрос, настроенный на возврат файла.</b> У узла «HTTP-запрос» есть настройка «формат ответа»; при значении
    «файл» тело ответа сохраняется как <code>File</code> вместо разбора как текста или JSON — удобно для скачивания
    бинарных данных (PDF, изображение, архив) с любого API. Та же настройка позволяет передать <code>File</code> в
    качестве тела самого запроса — для загрузки файла в API, ожидающий сырые байты.
  </li>
  <li>
    <b>Ручная загрузка.</b> Вкладка проекта <b>Files</b> (см. ниже) позволяет загрузить файл вручную — удобно, чтобы
    дать сценарию что-то на обработку во время тестирования, не дожидаясь реального триггера.
  </li>
  <li>
    <b>Действие «Создать файл из текста».</b> Превращает строку, собранную сценарием (CSV, JSON-документ, отрендеренную
    HTML-страницу), в <code>File</code>, чтобы её можно было отправить дальше или скачать так же, как любой другой файл.
  </li>
</ul>

#### Что можно делать с File

<ul>
  <li>
    <b>Прочитать как текст</b> — действие «Прочитать файл как текст» загружает содержимое файла в строковую переменную,
    отказывая для файлов сверх настраиваемого размера (состояние сценария должно оставаться небольшим; крупные файлы
    предназначены для передачи между узлами, а не для хранения в переменной).
  </li>
  <li>
    <b>Отправить в Telegram</b> — «Отправить файл» доставляет <code>File</code> в чат как фото, документ, видео, аудио
    или голосовое сообщение (тип определяется автоматически по mime либо выбирается явно).
  </li>
  <li>
    <b>Приложить к запросу AI</b> — «Вызвать AI»/«AI Choice» принимают список вложений <code>File</code> (изображения и,
    если модель поддерживает, документы), чтобы модель «видела» их вместе с промптом.
  </li>
  <li>
    <b>Распознать речь</b> — «Вызвать AI (распознавание)» превращает аудио <code>File</code> (например, голосовое
    сообщение из Telegram) в текст.
  </li>
  <li>
    <b>Удалить</b> или <b>заново получить по id</b> («Информация о файле»), если сохранён только его id где-то ещё
    (строка в базе данных, см. интеграции с базами данных), а не полная ссылка.
  </li>
</ul>

#### Публичные ссылки — по желанию

<p>
  По умолчанию <code>File</code> доступен только изнутри — из сценариев самого проекта и с вкладки Files, но никогда по
  голой ссылке, которую кто-то мог бы угадать или которой поделились. Действие «Опубликовать файл» включает публичную
  ссылку без авторизации (длинный неугадываемый токен, а не сам id файла) — по ней файл может открыть кто угодно; «Снять
  с публикации» выключает ссылку обратно, не удаляя сам файл. Удаление файла немедленно аннулирует любую ссылку на него.
  Это намеренно отделено от отправки файла в Telegram или вложения в запрос AI — оба этих сценария работают и без
  публикации, поскольку байты файла передаются напрямую, а не через ссылку, которую должна забирать третья сторона.
</p>

#### TTL и квоты

<p>
  Каждый файл учитывается в двух ограничениях: максимальный размер одного файла и максимальный суммарный размер файлов
  проекта — загрузка сверх любого из них отклоняется. Файлы также истекают автоматически, если сценарий явно не попросил
  иначе: файл, созданный запуском на dev-стенде, по умолчанию удаляется через сутки, файл, доставленный Telegram в чат,
  — через неделю, а файл, созданный <b>опубликованным</b> (production) запуском, не истекает сам по себе никогда. Эти
  значения по умолчанию администратор может менять для конкретного пользователя (см.{' '}
  <a href="./administration/">«Администрирование»</a>) — так развёртывание может повысить или понизить их для отдельной
  учётной записи, не трогая значения по умолчанию для всех остальных.
</p>

#### Вкладка Files

<p>
  У каждого проекта есть вкладка <b>Files</b> (рядом с Runs), где перечислено всё, что сценарий — или ручная загрузка —
  положил в хранилище: имя, размер, тип, кем создан, когда истекает и опубликован ли он. Отсюда можно скачать, удалить,
  загрузить новый файл или переключить публичную ссылку, а также увидеть, сколько квоты проекта уже занято.
</p>
