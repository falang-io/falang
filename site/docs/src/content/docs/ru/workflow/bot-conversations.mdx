Триггеры **«При сообщении»** и **«При команде»** ботов Telegram, MAX и VK решают две вещи: на какие чаты реагировать
(настройка **«Чаты»**) и в какой **запуск** сценария отправить очередное сообщение (настройка **«Диалог»**). Обе
задаются при создании триггера; значок «?» рядом с ними ведёт на эту страницу.

## Что такое запуск

**Запуск** (выполнение) — один проход сценария со своими переменными. Он может длиться долго: пока бот ждёт ответа на
вопрос, ждёт сообщения или стоит на блоке «Ждать», запуск продолжает работать и помнит всё, что было до этого. Запуск
заканчивается, когда сценарий доходит до конца (или падает с ошибкой).

У каждого запуска есть идентификатор. Его собирает триггер: из документа, чата и — в зависимости от настройки
«Диалог» — пользователя или события:

| Диалог | Идентификатор запуска |
| --- | --- |
| Один запуск на чат | `<префикс>-<документ>-<chatId>` |
| Один запуск на пользователя в чате | `<префикс>-<документ>-<chatId>-<userId>` |
| Новый запуск на каждое сообщение | `<префикс>-<документ>-<chatId>-<номер события>` |

Префикс — `tg`, `max` или `vk`. Входящее сообщение доставляется по этому идентификатору:

- **запуска с таким идентификатором нет** (ещё не было или уже закончился) — начинается новый запуск, сценарий
  выполняется с начала, сообщение лежит в переменной `message`;
- **запуск с таким идентификатором уже идёт** — новый запуск **не** начинается, сообщение передаётся в идущий (что
  с ним там происходит — [ниже](#сообщение-во-время-идущего-запуска)).

Идентификатор включает документ, поэтому разные триггеры (например, «При сообщении» и «При команде» `/help`) всегда
живут в разных запусках, даже в одном чате.

## Настройка «Чаты»

- **Любые чаты** (по умолчанию) — личные чаты, группы и каналы.
- **Только личные чаты.**
- **Только группы и каналы.**

Сообщение обрабатывает первый подходящий по фильтру документ, поэтому в одном проекте можно держать отдельный
сценарий для лички и отдельный для групп.

## Настройка «Диалог»

### Один запуск на чат

Значение по умолчанию. На чат — один запуск: пока он идёт, все сообщения этого чата приходят в него, новый начинается
только после его окончания.

- **В личке** это обычный разговор с пользователем: бот задал вопрос, человек ответил — ответ пришёл в тот же запуск.
- **В группе** все участники делят один запуск. Пока он идёт, сообщения и команды **любого** участника попадают в него,
  а не начинают свой. Это подходит, когда бот ведёт одну общую «игру» на чат; для отдельного разговора с каждым
  участником выберите следующий режим.

### Один запуск на пользователя в чате

У каждого участника чата — свой запуск. Сообщения Ани и Бориса в одной группе не мешают друг другу: каждый проходит
анкету, викторину или оформление заказа сам. В личке ведёт себя так же, как «Один запуск на чат» (в чате один
человек). Сообщение без отправителя (пост канала) попадает в запуск чата.

### Новый запуск на каждое сообщение (без состояния)

Каждое сообщение начинает отдельный запуск, который ничего не знает о предыдущих сообщениях. Подходит для
коротких реакций без памяти: антиспам, удаление ссылок, ответ на ключевое слово. Вопросы с кнопками и «Ждать
сообщение» в таком режиме бессмысленны — следующее сообщение всё равно начнёт новый запуск.

## Сообщение во время идущего запуска

Новое сообщение из чата обрабатывается в таком порядке:

1. **Команда, у которой есть свой триггер «При команде»**, уходит в запуск этого триггера (у него свой
   идентификатор, см. выше).
2. **Если запуск ждёт сообщения на блоке «Ждать сообщение»** (от этого пользователя или от любого участника чата),
   сообщение достаётся этому блоку: сработает ветка «message», текст доступен как `reply`.
3. **Иначе сообщение отправляется по идентификатору запуска** — и если такой запуск уже идёт, сценарий для этого
   сообщения **заново не выполняется**.

В последнем случае сообщение не ставится в очередь и не обрабатывается отдельно: идущий запуск просто **заменяет
переменную `message` новым сообщением** и продолжает с того места, где был. Ответ на вопрос с кнопками приходит
отдельно (нажатием кнопки) и `message` не меняет.

**Пример.** Группа, триггер «При команде» `/quiz`, «Диалог: один запуск на чат». Сценарий задаёт вопрос с кнопками,
потом поздравляет `message.from.firstName`.

1. Аня пишет `/quiz` — начинается запуск, бот задаёт вопрос и ждёт нажатия.
2. Борис пишет `/quiz` — запуск для чата уже идёт, поэтому новая викторина **не** начинается. Его сообщение попадает в
   запуск Ани, и `message` там теперь — сообщение Бориса.
3. Аня нажимает кнопку — сценарий продолжается и поздравляет… Бориса.

Борис ответа на свою команду не получит. Следующий `/quiz` в этом чате начнёт новую викторину только после того, как
закончится текущая. В личке то же самое случается, если человек отправляет сообщение, пока сценарий ещё не закончился
(например, второй раз пишет `/start`): `message` в идущем запуске становится последним сообщением.

### Как не попасть в ловушку

- **Сохраняйте нужное из `message` в начале сценария** — блоком «Новая переменная», например
  `const user = message.from` или `const chatId = message.chat.id`. Новое сообщение заменяет только саму переменную
  `message`, сохранённые значения остаются прежними.
- **Нужен разговор с каждым участником группы** — ставьте «Один запуск на пользователя в чате».
- **Реакция без памяти** (модерация, ответы на ключевые слова) — «Новый запуск на каждое сообщение».
- **Нужно следующее сообщение пользователя** — берите его блоком «Ждать сообщение», а не из `message`: блок получает
  ответ сам, с таймаутом и с фильтром по отправителю.
- **Длинные паузы** (блок «Ждать», вопрос с большим таймаутом) удерживают запуск — всё это время новые сообщения чата
  попадают в него. Не держите запуск дольше, чем нужно.

## Команды в группах

Команда в группе обрабатывается так же, как в личке: по ней выбирается триггер «При команде», затем работают «Чаты» и
«Диалог». Отличия:

- Telegram дописывает к команде имя бота (`/start@my_bot`); оно отбрасывается, команда совпадает с триггером `start`.
- Получит ли бот команду, решает мессенджер. Telegram-боту с включённым privacy mode в группе гарантированно приходят
  команды с явным `@имя_бота`, ответы на его сообщения и служебные события; MAX и VK тоже позволяют ограничить, какие
  сообщения беседы видит бот.
- Кнопка-команда из «Отправить сообщение с кнопками» срабатывает так, будто нажавший сам отправил эту команду, — с теми
  же правилами, в группах тоже.

<Aside type="caution">
  Кнопки **вопроса**, нажатые в группе, возвращаются в ожидающий запуск только в режиме «Один запуск на чат». В режимах
  «на пользователя» и «на каждое сообщение» нажатие не доходит до запуска и записывается в журнал запусков как
  предупреждение `UnroutableGroupAnswer`. Задавайте вопросы в личке или оставьте «Один запуск на чат».
</Aside>

<Aside>
  [Тест-бот платформы](../test-bot/) работает только в личных чатах: в группе он лишь присылает
  уведомление. Проверить поведение в группе можно на собственном боте.
</Aside>
