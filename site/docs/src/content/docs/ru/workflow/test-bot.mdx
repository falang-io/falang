<p>
  Пока вы делаете бота для мессенджера, собственный бот не нужен. Если администратор настроил общий <b>тест-бот</b> для
  мессенджера, тестовый стенд вашего проекта может использовать его: вы подключаете свой личный чат к проекту, и всё,
  что вы пишете тест-боту, попадает в ваш сценарий. Сейчас это работает для Telegram, MAX и VK.
</p>

#### Для пользователя

<ol>
  <li>
    Откройте <b>Интеграции</b>, добавьте (или измените) учётные данные Telegram, MAX или VK и включите{' '}
    <b>Dev: тестировать в боте платформы</b>. Поле токена для разработки можно оставить пустым; токен для продакшена —
    по-прежнему токен вашего собственного бота.
  </li>
  <li>
    После сохранения откроется окно с одноразовой ссылкой и QR-кодом (позже оно доступно по кнопке <b>Подключить чат</b>
    ). Откройте ссылку в мессенджере (<code>t.me/…</code> для Telegram, <code>max.ru/…</code> для MAX,{' '}
    <code>vk.me/…</code> для VK) и нажмите <b>Start</b> (в MAX и VK — <b>Начать</b>) — тест-бот ответит, что чат
    подключён к вашему проекту.
  </li>
  <li>
    Запустите тестовый стенд и напишите тест-боту. Сообщения попадают в триггеры проекта, а ответы сценария приходят в
    тот же чат.
  </li>
</ol>

<p>
  В окне виден список чатов, подключённых к этим учётным данным; <b>Отключить</b> убирает чат.
</p>

#### Что важно знать

<ul>
  <li>
    <b>Меню команд в Telegram.</b> В подключённом чате Telegram кнопка «/» показывает команды вашего проекта (его
    триггеры «по команде», с названиями документов-триггеров) и служебную команду тест-бота; меню обновляется при
    подключении и при каждом запуске тестового стенда, а после отключения чата остаётся только служебная команда. В MAX
    и VK меню команд для отдельного чата нет, поэтому там ничего не показывается.
  </li>
  <li>
    Подключаются только <b>личные чаты</b>; группы тест-бот игнорирует (один раз сообщает об этом).
  </li>
  <li>
    Чат связан с одними учётными данными одного проекта; повторное подключение переносит его. Ссылка работает один раз и
    15 минут.
  </li>
  <li>
    Подключение живёт <b>15 минут</b> (администратор может изменить) <i>с последней активности</i> — каждое сообщение и
    каждый ответ сценария продлевают его. Когда оно истекло, бот просит открыть свежую ссылку.
  </li>
  <li>
    Служебная команда <code>/falang</code> в чате показывает, к какому проекту он подключён, а <code>/falang off</code>{' '}
    отключает. Любой другой текст, включая обычный <code>/start</code>, уходит в сценарий. (Администратор может
    переименовать команду.)
  </li>
  <li>Если тестовый стенд остановлен, тест-бот предложит запустить его в редакторе.</li>
  <li>
    Песочница действует только на <b>тестовый стенд</b>. Опубликованная (prod) версия всегда использует токен вашего
    собственного бота.
  </li>
  <li>
    Общий бот защищён лимитами: ему пересылаются только сообщения подключённого чата, а число вызовов на проект и на чат
    ограничено.
  </li>
</ul>

#### Для администратора (self-hosted)

<p>
  В приложении администратора откройте <b>Тестовые боты</b>. Для каждого поддерживаемого мессенджера создайте бота (для
  Telegram — через @BotFather, для MAX — на платформе ботов MAX, для VK — сообщество с разрешёнными сообщениями и ключ
  доступа сообщества с правом на сообщения) и вставьте его токен: токен проверяется, показывается имя бота. Здесь же
  задаются <b>срок подключения</b> (минуты с последней активности, по умолчанию 15), имя служебной команды, повторная
  проверка токена и удаление тест-бота (подключения при этом остаются неактивными).
</p>
<p>
  Тест-бот обслуживает сам backend: если задан <code>GATEWAY_PUBLIC_HOST</code>, используется webhook, иначе long
  polling. Запускайте одну реплику backend — две будут конкурировать за одни и те же обновления.
</p>
