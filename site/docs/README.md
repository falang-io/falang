# falang docs site

The Falang documentation site — [Astro Starlight](https://starlight.astro.build),
deployed to `docs.falang.io` (English) / `docs.falang.ru` (Russian).

Split out from the `../main` marketing project (which used to serve docs at
`/docs/**`) because Starlight's sidebar (`slug`/`autogenerate` entries,
titles from frontmatter), search (Pagefind), and table of contents all
assume Starlight owns the site's routing from the root — nesting it under a
path prefix alongside a separate custom homepage isn't supported. Running
it as its own project, on its own subdomain, gets the full feature set with
no fighting the framework. See `../main/src/components/Nav.astro` for the
cross-link back to the marketing site, and this project's
`src/components/Header.astro` for the link back the other way plus the
language switch (no in-page locale routing — same domain-per-locale model
as `../main`, just on `docs.*` instead of the bare domain).

Deliberately not under the monorepo's `packages/`, same reasoning as
`../main`: standalone npm project, own `package.json`/lockfile, not part of
the root npm workspaces.

## Two domains, two builds

Same model as `../main`: one codebase, two static outputs, selected via the
`SITE_LOCALE` env var at build time (see `astro.config.mjs` and
`src/i18n/locale.ts`):

```
npm run build       # builds both: dist/en (docs.falang.io) and dist/ru (docs.falang.ru)
npm run build:en    # SITE_LOCALE=en astro build --outDir dist/en
npm run build:ru    # SITE_LOCALE=ru astro build --outDir dist/ru
```

## Development

```
npm install
npm run dev:en   # http://localhost:4321
npm run dev:ru   # http://localhost:4322
```

`npm run check` type-checks the project (`astro check`).

## Publishing

`docs.falang.ru` (Russian) is published manually via:

```
npm run publish:ru   # build:ru, then scp dist/ru/. to the falang-ru host
```

This builds the Russian site and copies it with `scp -r dist/ru/. falang-ru:/projects/falang-docs/`
(`falang-ru` is a pre-configured SSH host alias). `scp` overwrites files in
place but does not delete files that no longer exist in the local build —
if a page is removed, its stale output stays on the server until manually
cleaned up. `docs.falang.io` (English) has no publish script yet.

## Content

- `src/content/docs/<locale>/**` — one `.mdx` file per page. `index.mdx` at
  a directory's root is that directory's landing page. Page titles/sidebar
  labels come from each file's frontmatter `title` — no separate menu file
  to keep in sync.
- `src/components/ImageRow.astro` / `Gallery.astro` — the two recurring
  content patterns (a text+image side-by-side row; one or more centered
  images/video), replacing the old site's hand-rolled
  `docs-img-wrapper`/`one-image`/`triple-images` markup+CSS classes.
- `astro.config.mjs`'s `sidebar` array is the source of truth for sidebar
  structure and grouping.
- `src/styles/custom.css` (`customCss` in `astro.config.mjs`) — besides the
  `TwoColumnContent` width-capping fix (see its own header comment), it also
  carries the "dark developer" theme match with `../main`'s redesign:
  Starlight's `--sl-color-accent*` tokens retinted to the same teal hue
  (172°) in both light and dark mode, and `--sl-font-mono` plus a heading
  selector list (`.sl-markdown-content h1`–`h6`, `#_top` — Starlight's page
  `<h1>`, `.site-title`) switched to a monospace stack, matching `../main`'s
  headings. Body copy stays Starlight's default sans-serif; only headings
  and the nav logo go monospace. Starlight's own light/dark toggle
  (`ThemeSelect`) is unchanged — both modes are retinted, neither is forced.

### Why the sidebar uses manual `slug` entries instead of `autogenerate`

Each build only reads one locale's directory (the collection's `base` in
`content.config.ts` is `./src/content/docs/${SITE_LOCALE}`, so ids come out
locale-flat with no `en/`/`ru/` prefix — same per-locale-build model as
`../main`). Starlight's `autogenerate` sidebar entries, however, match
content by each entry's **on-disk file path** relative to a hardcoded
`src/content/docs` (see `@astrojs/starlight/utils/collection.js`'s
`getCollectionPathFromRoot`), which has no idea about this collection's
actual locale-scoped `base` — every entry's real path looks like it's
inside a `<locale>/` subdirectory that `autogenerate` never matches, so
autogenerated groups silently render empty. Manual `slug` entries use each
entry's content-layer id instead (already locale-flat), so they're
unaffected — see the comment above `sidebar` in `astro.config.mjs`. Revisit
if the per-locale-directory content layout ever changes.

## Known pre-existing content quirks

Carried over verbatim from the old site rather than silently "fixed" in
migration — worth a look before launch:

- RU `logic/index.mdx` title: "Конструтор логики" (missing a "к").
- RU `text.mdx` has a stray "4" inside a word: "на к4оторую".
- RU `basics.mdx` frontmatter (`description`/keywords) duplicates the docs
  root page's, not `basics`-specific text — looks like a copy-paste slip in
  the original old site's `docs-menu.ts`.
