# Text and TypeScript packages

**Text domain** (`packages/text/`):

- `dto` — `@falang/text-dto`: DTOs for text-specific nodes. Since ADR 0049 (private): a `timer` mod kind (`modCfg`) allowed on `action`/`link`/`if`/`switch`/`foreach`/`while` hosts. Since 2026-11-05: `return` is `getOutConfigSimple` (no text, like `break`/`continue`; a stored `data` of an older document is dropped on parse) and `@falang/text-scheme` draws it as a pseudo-block; the old-app converter keeps a text return's text as an `action` right before it.
- `scheme` — `@falang/text-scheme`: scheme blocks and editors for text-based content. The main text block (`blocks/html/`, `htmlBlockConfig`) is a Lexical-backed rich text editor (bold/italic/underline/strikethrough, alignment, lists, resizable/centerable images stored as an inline `span`-based `ImageNode`) — `data` is still a plain HTML string (`stringDataType`; its `html-block.css` is loaded by the browser-only `@falang/text-scheme/src/browser.js`, which browser hosts import once — the package index has no CSS import so it loads in plain Node), rendered read-only via `dangerouslySetInnerHTML` and parsed back into Lexical nodes (`lexical/html-io.ts`'s `htmlToNodes`/`nodesToHtml`) on edit; replaced the old bare-`contentEditable` `blocks/text/` (deleted). Plus `contour-function-footer` (a `<select>`, unaffected). Since ADR 0049 (private): `timer` side-icon config (`sideIconConfig` + `timerShape`, left placement, resizable, text block per its `IBlockConfig`) and a "Timer" context-menu entry via `buildModsMenu` on the six hosts.

**TypeScript domain** (`packages/typescript/`):

- `dto` — `@falang/typescript-dto`: TS-specific DTOs (functions, arrays, enums, expressions, object definitions, external API items).
- `common` — `@falang/typescript-common`: shared TS input utilities (text, checkbox, color, file, JSON, markdown, date-time, array, and object property inputs); also owns scope tracking (`collectScopeVariables`, see "TypeScript scope tracking" below). Since ADR 0046 (private): `getScopeContributions(node)` (plural) flattens a `magic` node into its children's contributions recursively (used by `collectScopeVariables` and the compiler's debug walk); a `magic` parent is transparent, and the popup-only `magic-function-body` contributes `data.outerScope` and is a walk boundary.
- `scheme` — TS scheme blocks (currently scaffolded: `common.block.config.ts`). Since ADR 0046 (private): `functionalSchemeFactory` takes an optional `defaultInsertNodeName?: () => string`, read on every valence-point click and used wherever the click would insert the fallback `'action'` (a `children: true` parent) — how a host makes a plain click insert `'magic'`. Since 2026-10-06: `extraInsertableGroups` (`IInsertableGroup { groupKey?, label?, items }[]` or a getter read on every menu build) adds further named submenus next to `extraInsertableItems`' "Integrations" — the Arduino IDE's "Arduino"/"Device" groups. Since ADR 0068 (private): `src/field-check/` — what a field looks like to the type checker as pure data shared by the editors and the background check. `describeCheckedFields(node, { projectService })` returns `ICheckedField[]` (`code`: `field`/`prefix`/`value`/`suffix`/`allowEmpty?`/`skipValues?`; `identifier`: `value` + `scopeNames`) from a per-node-kind registry (`registerFieldDescriber(nodeName, fn)`, `registerFieldDescriberResolver({ resolve(node) })` for families of kinds — how `@falang/workflow-scheme` will plug its integration blocks in); the TypeScript blocks (action, while/switch/switch-option/throw, if, return, log, create-var, arr-\*, foreach, from-to-cycle, call-function, call-api) are registered built in. The editor stores build their `CodeModelStore` prefixes from the same helpers (`prefix-builders.ts`, `scope-context.ts` — `buildNodeScopeCode`/`buildForcedTypePrefix`/the dynamic `call-function`/`call-api` scope resolver, moved out of `ExpressionBlockEditorStore`; `model-text.ts`'s `buildModelText`/`MODULE_MARKER` is the one place the final text is assembled), and a test asserts descriptor text equals each editor store's `fullValue`. `MonacoCheckPool({ size = 1, cacheSize, getMonaco?, getLibKey?, isAvailable? })` owns dedicated models `file:///__validation-<n>.ts`, `check(fullText, regions?)` rewrites a free slot's model and asks the TS worker for syntactic + semantic diagnostics (error category only, LRU cache keyed by text + `getMonacoLibKey()`); `createTypescriptFieldsValidator({ pool? })` (`source: 'typescript'`; an error on a hidden prefix/suffix line gets `HIDDEN_LINE_NOTE` appended) and `createTypescriptValidators`/`createTypescriptValidationModule` are the one-line host wiring; without an installed Monaco code fields are skipped (one warning), identifier fields (`validateVariableName`) still run. `MonacoCheckPool` retries `getTypeScriptWorker()` for up to ~10 s: Monaco loads its TypeScript contribution lazily when the first `typescript` model appears and throws "TypeScript not registered!" until then (found live — a document opened before any editor model showed no errors). Wired into the workflow client and both desktop IDEs (see their bullets).
- `scheme` note (ADR 0069 (private), phases 2-3): `TypescriptProjectService.numberTypesMode` (`'typescript'` default | `'portable'`) and `defaultFloatType` (`float64`; app-arduino `float32`) are set by the host's project container (`@falang/desktop-agent-host`: app-sketch `logic` and app-arduino are `portable`, the workflow product stays `typescript`). All type pickers (create-var, function parameters/return type, object-property, external-api-item, table and antd-sidebar variants) are one `VariableTypeSelect` (`block-elements/variable-type/`: `integer`/`float`/`decimal` with width / digits 1-18 / decimals instead of `number`, no `any`/`enum` in portable mode; `buildDefaultVariableType`, `choiceOf`; views show `typescript-dto`'s `describeVariableType` via `describeVariableTypeForMode`); a `number(any)` value in portable mode shows as an empty choice, never silently replaced. `createPortableTypesValidator()` (`portable-types/`, `source: 'portable-types'`) reports an error on every `number(any)`/`any`/`enum` found anywhere in a node's data (active only in portable mode); `createTypescriptValidationModule({ portableTypes: true })` adds it, `createPortableTypesValidationModule()` is the structure-document module (`SKETCH_VALIDATED_DOCUMENT_TYPES`: `function`, `objects-structure`, `external-api-structure` of a `logic` project). `createDesktopAgentSession({ portableNumbers })` adds a `PortableNumbersContextProvider` line; `create-var`/`function-body` have `NODE_KIND_NOTES` (`node-kind-notes-numbers.ts`).
- `scheme` note (2026-11-08): struct pickers read `TypesRegistryStore.pickerTypes` (every registered type narrowed by a host's `setPickerFilter(TTypesPickerFilter)` — a batch filter run in a MobX computed; `types` itself is never filtered, Monaco scope and the compilers still see everything) and pick through `StructTypeSelect` (`block-elements/variable-type/struct-type-select.cmp.tsx`, exported: antd `Select` with substring search over name and id, `matchesStructSearch`; used by `VariableTypeSelect` in both variants and by `@falang/workflow-scheme`'s result-type field). Without a filter (desktop) every type is offered.
- `scheme` note (2026-10-03, second round): `return` has its own block/icon/shape (`blocks/return/`, `ReturnIconStore` — label-only like `break`/`continue` in a function without a return value (since 2026-10-04: one cell high, a fixed `CELL_SIZE_4` wide whatever `meta.width` says, not resizable), otherwise a "Return" title over a Monaco field typed `typeof returnValue`; a return created from the outs menu in such a function defaults to `returnValue`; shapes get `IBlockShapeViewProps.icon` for this). `arr-push`/`arr-unshift` switch their value field to the text-with-`${…}` editor when the language service resolves the array's element type to `string` (`probeIsStringType` over Monaco's TS worker; `string-value-expression.ts` converts between the stored TS expression — `'text'` or a template literal — and the edited text). Since 2026-10-21 `create-var` does the same for a `string` variable (decided statically from `variableType`, no probe; empty text = no initial value; changing the type converts the value between the two forms), and both blocks show a literal value as text via `StringValueViewComponent` (`block-elements/template-string/string-value-view.cmp.tsx`). `CodeModelEditingComponent` also works outside a scheme (no pan/zoom to follow).
- `scheme` note (2026-11-08): `function-footer` (every `function`/`trigger-function` document of the workflow product, app-sketch `logic` and app-arduino) is a fixed "End"/"Конец" label (`blocks/function-footer/`, locale key `function-footer:end`): no editor, `FunctionFooterIconStore` keeps it `CELL_SIZE_4` wide and non-resizable whatever an older document stored in `meta.width`; the node's stored `data` is ignored. `@falang/scheme` now exports `rectangleRoundedShape`.
- `scheme` note (2026-10): `while`/`switch`/`switch-option`/`return`/`throw` fields use `blocks/expression/` (a scope-aware Monaco code field; `decodeLegacyHtml` un-escapes `&lt;`-style text saved by the former HTML text block), and the plain `textBlockConfig` is now a plain-text (`textContent`) editor. Inline (`compact`) Monaco fields move focus on Tab/Shift+Tab (`tab-navigation.ts`), doing nothing at the first/last field.
- `agent` — `@falang/typescript-agent`: `@falang/agent`'s one TypeScript-domain extension, `ScopeVariablesContextProvider` (see ADR 0009 (private)) — feeds the LLM the identifiers in scope at a node via `collectScopeVariables`.
