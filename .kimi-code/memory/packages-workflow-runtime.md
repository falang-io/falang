# Workflow runtime packages

**Workflow domain** (`packages/workflow/`) — everything specific to the n8n-like workflow-engine product; see ADR 0002 (private):

- `dto` — `@falang/workflow-dto`: workflow-specific node DTOs (triggers, HTTP call, wait, human approval, …) — still scaffolded/empty; the MVP runs on the existing `typescript` nodes first.
  Since ADR 0055 (private): `src/project-layout/` — the fixed root sections of a workflow project (`WORKFLOW_FIXED_FOLDERS`: `triggers` → `trigger-function`, `functions` → `function`, `types` → `objects-structure`; `TWorkflowFixedFolderKind`) and pure helpers over plain tree folders/documents: `isFixedFolder`, `sectionForDocumentType`, `findSectionFolder`, `resolveFolderSection` (walks `parentId` up), `checkDocumentPlacement`/`checkFolderPlacement` (`null` or a human/LLM-readable reason naming the right section and its id) and `normalizeWorkflowProjectLayout(folders, documents, { createId })` (ensures the sections, moves root documents into them, splits mixed user folder trees by section, drops empty ones; idempotent) — shared by backend, client and agent tools.
  Since ADR 0059 (private): `src/run-journal/run-journal.ts` is the run journal's one shared contract (backend, runner, compiler import it; client-common mirrors it in `api-types.ts`): kinds `log`/`trigger`/`user-input`/`ai`/`message-out`/`error`, levels, `IRunJournalWireEntry` (`ts` epoch ms) / `IRunJournalIngestBody` (≤ 500 entries), size limits (message 1024 / data string 32768 / data 128 K chars), `RUN_JOURNAL_METADATA_KEYS` (what survives "don't store texts"), the read page `{ entries, hasMore }`, the sink (`falangJournal.append`, workflow helper `__falangJournal`), the node header `falang-node` (`{ documentId, nodeId | null }`), the compiled export names (`__falangActivityVendors`/`__falangActivityJournal`/`__falangActivityParams`/`__falangPositionStack`), `IRunJournalActivitySpec`, the AI text result `{ text, usage?, model? }` and the source-key builders.
  Since 2026-10-28: `src/wait/wait-nodes.ts` — the `wait` node (`WAIT_NAME`, `waitNodesGroup`): a leaf whose `data` is a TypeScript duration expression (milliseconds, or a duration string literal such as `'1 day'`).
