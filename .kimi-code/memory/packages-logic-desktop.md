# Logic and desktop packages

**Logic domain** (`packages/logic/`) — the "logic constructor": compiling one visual project into source code for several target languages; see ADR 0019 (private):

- `dto` — `@falang/logic-dto`: `TExportLanguage`/`ILogicExportConfiguration` (which languages to export, and where).
- `scheme` — `@falang/logic-scheme`: `LogicExportConfigurationStore` plus the export-configuration panel (the only logic-constructor-specific UI; the editing model itself lives in `@falang/typescript-*`).
- `constructor` — `@falang/logic-constructor`: the compiler. `compileExpression` type-checks one expression against a scope via a real `ts.Program` and emits it per target (`ts`/`js` directly, everything else through an `ILanguageAdapter` + the shared `walk-expression.ts` walker). On top of that sit five statement-level project compilers — `compileCppProject`/`compileGoProject`/`compileRustProject`/`compileSharpProject`/`compileTsProject` — each with its own `*-statement-context`/`*-leaf-emitters`/`*-control-flow-emitters`/`*-type-name` files and a shared core (`cycle-info.ts`, `function-signature.ts`, `log-template.ts`, `struct-registry.ts`). Multi-level `break`/`continue` splits the targets in two: cpp and C# have no labeled break/continue and use the old app's `_break_level`/`_continue_level`/`_switch_break` counters (`cycle-info.ts`); Go, Rust, and TS have real loop labels and use those instead. `compileTsProject` (ADR 0019 (private) "TypeScript target — per-document files matching the old app's layout") is the first _multi-file_ target — it returns `ICompiledProjectFiles` (`{ files: Record<string, string> }`, `compiled-project-files.ts`) instead of a single string, one `.ts` file per `function`/`objects-structure`/`external-api-structure` document plus a `_falang.ts` (`Apis`/`FalangGlobal`), matching the old app's own `code/ts/src/falang/*.ts` layout; a non-void function auto-declares a `returnValue` local (the old app's own convention — many real documents mutate it via plain `action` nodes with no explicit `return` node at all) initialized to a recursively-populated empty value and returns it unconditionally at the end, coexisting with any explicit `return` nodes mid-body. `compileRustProject` is the second multi-file target (ADR 0019 (private) "Rust target — old-app layout" implementation notes) and shares this same `ICompiledProjectFiles` shape — one `.rs` file per `function`/`objects-structure` document plus `mod.rs` and `falang_global.rs`, matching the reference `code/rust/src/falang/*.rs` layout of the user's real `#![no_std]` embedded host project. Replaces the previous single-file/`OnceLock`-static design: every compiled function takes a trailing `_apis: &mut dyn crate::falang::falang_global::Apis` parameter unconditionally (dependency injection for `call-api`, which now compiles to `_apis.<ApiDoc>_<Group>_<Endpoint>(args)` against one flattened `Apis` trait in `falang_global.rs` rather than a per-API `OnceLock<Box<dyn Trait>>` static); struct/array parameters are `&T` references (cloned only where a borrowed/reused value gets stored — `create-var`, a bare `action` assignment, `arr-push`/`arr-unshift`/`arr-insert`'s own value, an array literal's elements), scalars stay by value; `String`/`Vec` route through `alloc::string::String`/`alloc::vec::Vec` unconditionally (valid under both `std` and `#![no_std]`, no per-target flag needed); and a non-void function gets the identical auto-declared/auto-returned `returnValue` local the TS target's own `compile-ts-function.ts` already established (see above), which also fully subsumed the target's previous `needsTrailingPanic`/`panic!("unreachable")` synthesis (a non-void function's body now always literally ends in `return returnValue;`, itself a terminating statement). Real-build-verified: `cargo build`/`cargo build --release` for `thumbv7m-none-eabi` succeeded against a copy of the user's own `example-snake` host crate with its generated `src/falang/*` replaced (real external deps — `stm32f4xx-hal`, `ili9341` from a git branch — resolved and compiled over the network), alongside all five Rust `npm run test-e2e-logic` compile-and-run tests staying green. Since ADR 0035 (private): every `*-control-flow-emitters.ts`'s `emitWhile` gained its own independently-implemented `resolveWhileCondition`, reading `meta.trueIsMain` and negating the condition when it's `true` (same convention as that file's own `resolveIfBranches`/`meta.trueOnRight`). Since ADR 0069 (private) phase 4 (`decimal(D, S)`, a signed fixed-point `raw × 10^-S` over a 64-bit `raw`, half away from zero everywhere): `numeric-coercion.ts` promotes decimal ⊕ decimal to the larger scale, decimal ⊕ integer to the decimal, decimal ⊕ float to the float (`numericLiteralValue` reads a literal exactly from its source text, a fractional literal next to a decimal is a decimal of its own scale); `walk-decimal.ts` is the decimal half of the walker (operands rescaled to one scale first so a target only needs same-scale primitives, stores/compound assignments/array literals converted through the optional `targetType`, `print` for `log`/template segments) over a per-target `IDecimalCodegen` (`decimal-codegen.ts`, `ILanguageAdapter.decimal`) — `decimal/cpp-decimal.ts` (`FalangDecimal<S>`, no STL, hidden friends and static members only so the Arduino sketch preprocessor has no free function to trip on; inlined into `falang.cpp` / the `.ino` when used), `go-decimal.ts` (`int64` raw + `falangDec*` helpers appended to the file), `rust-decimal.ts` (`FalangDecimal<const S: u32>` in `falang_decimal.rs`, `core` only, `#![no_std]`-compatible), `sharp-decimal.ts` (native `decimal` + a `FalangDec` helper class, every `*`/`/`/store rounded), `ts-decimal.ts` (`number` holding the real value, `_falang_decimal.ts` with BigInt helpers; the TS/JS expression rewrite in `ts-integer-semantics.ts` is now an edit list). Statement emitters pass the declared type (`create-var`, call arguments, `return`, `arr-push`/`arr-unshift` element) as `targetType` and print `log` segments through the `compile*ExprForPrint` variants; `ICppFunctionSignature`/`IGoFunctionSignature` gained `parameters`. A `length` is a signed `int32` in every target (C++ `static_cast<int32_t>(….size())`, Go `int32(len(…))`, Rust `(….len() as i32)`; `resolveVariableInfo` types it so), and the C++ string type is a parameter (`variableInfoToCppType`'s `stringType`, `ICppCompileParams.stringType`, default `CPP_STD_STRING_TYPE`). A whole-statement `x++`/`--x`/`x op= y` action is lowered to a plain assignment before compiling (`increment-statement.ts`, C++/Go/Rust/C# action emitters; the adapters map no `++`/`--`/compound operator). Known limits: a conditional expression's type is not resolved (a decimal inside `?:` is left to the target), there is no JS project compiler (the `js` expression target emits calls to `falangDec*`, `FALANG_DECIMAL_TS_RUNTIME` is exported), `D` is not checked at run time and the intermediate of `*`/`/` must fit a signed 64-bit integer.
- `export` — `@falang/logic-export`: `exportLogicProject({ projectDir, documents, exports })` runs every configured `ILogicExportConfigurationItem` (from `readLogicExportConfiguration`/`falang/config/logic-export.json`, `export-configuration-file.ts`) through the matching `compile*Project` and writes the result under `<projectDir>/<item.path>` — a single file (`falang.cpp`/`falang.go`/`Falang.cs`) for cpp/Go/C#, or every entry of `compileTsProject`/`compileRustProject`'s `ICompiledProjectFiles` for ts/rust (never deleting a stale file the current compile doesn't produce). Never throws per item — each `ILogicExportItemResult` carries its own `ok`/`files`/`errors`, so one broken target doesn't block the others.
- `e2e-tests` — `@falang/logic-e2e-tests`: compile-and-run tests. Each builds and runs generated source inside a pinned-toolchain Docker image (`docker/logic-{cpp,go,rust,sharp}-runner.Dockerfile`) and asserts its stdout against the old app's own `result.txt` (`expected-output.ts`), so every target must produce byte-identical output. Excluded from plain `npm test` (needs Docker) — run `npm run test-e2e-logic`.

**Desktop domain** (`packages/desktop/`) — standalone offline Electron products, each documented in its own ADR:

- `project-fs` — `@falang/desktop-project-fs`: plain Node (no Electron dependency) filesystem-backed project CRUD (`createProject`/`openProject`/`listTree`/document and folder CRUD) — the on-disk format every desktop app below shares: `falang.json` manifest (source of truth: ids, tree, and each entry's stored on-disk segment — `fileName` for documents, `dirName` for folders) + one `falang/schemes/<folder dirName chain>/<fileName>.json` per document (named after the scheme, project-tree folders are real directories; `layout.ts` sanitizes/deduplicates names case-insensitively, `reconcile-layout.ts`'s idempotent `reconcileProjectLayout`, run by `openProject`, is the v4 → v5 migration and self-heal) + `falang/config/` for domain-specific config files (e.g. `@falang/logic-export`'s `logic-export.json`), current `FORMAT_VERSION` 5; every operation that reads-then-writes the manifest or resolves a document path runs under a per-project in-process serial lock (`project-lock.ts`'s `withProjectLock`; not cross-process — `@falang/desktop-mcp` is a separate process) (`paths.ts` exports `MANIFEST_FILENAME`/`configDir`/`configFilePath`/`documentsDir`/`manifestPath`, etc.) — see ADR 0005 (private) "Implementation notes (on-disk layout v4 …)" and "(on-disk layout v5 …)". `openProject` migrates a v3 project (`project.json` + `documents/<id>.json`, the format's own previous version) to v4 in place on open (`migrate-v3.ts`, `isV3FormatProject`/`migrateV3Project`); `@falang/desktop-project-converter` migrates a v2 (old, pre-monorepo app) project straight to the current format. Also owns the desktop side of ADR 0029: the locks sidecar (`locks.ts`, `.falang-locks.json`), `writeAgentFiles` (`.mcp.json` + `CLAUDE.md` into a project folder; `CLAUDE.md` only-if-absent, `.mcp.json`'s `falang` server entry rewritten whenever it differs — the packaged command embeds the binary's path, which updates move — other servers kept, a file without a `falang` entry never touched; optional `mcpServerEnv`), and `watchProject` (`fs.watch` over `falang/schemes/` (recursive)/`falang.json`/the sidecar, debounced, with own-write suppression) that both apps use to reload externally edited documents and show the agent-lock overlay. Also ships `createGitVersionStore` (`src/versioning/`), an `IVersionStore` (`@falang/versioning`, see ADR 0025 (private)) over [isomorphic-git](https://isomorphic-git.org/) — private-or-enclosing repo resolution, `.gitignore` on first init, `falang/<short-oid>` annotated tags for named commits, a per-store serial promise queue, and `restore` via scoped `checkout`; staging covers `falang.json`, every document under `falang/schemes/`, and (enumerated generically, no domain-specific filename knowledge needed) every file under `falang/config/`. Sidecars (`.falang-locks.json`/`.falang-debug.json`/`.falang-versioning.json`/`.mcp.json`/`CLAUDE.md`) stay at the project root. Since ADR 0033 (private): `agent-sessions/agent-sessions.ts` persists agent chat sessions the same way documents are — one `falang/agent-sessions/<id>.json` file per session (`listSessions`/`createSession`/`getSession`/`renameSession`/`deleteSession`/`appendTurn`, plain async functions over `@falang/agent`'s `IChatSession`/`IChatTurn` types, type-only imported so this package stays React/MobX-free at runtime), not a single sidecar blob — deliberately no serial queue and no `watchProject` integration, since chat sessions are only ever written from inside the app itself. Since ADR 0054 (private): `falang/drivers/` (`DRIVERS_DIRNAME`/`driversDir`) is staged recursively by the git store and restore removes driver files absent from the restored commit; `watchProject` also watches it (lazily attached when it appears) and emits `{ kind: 'drivers' }`, with `markOwnDriversWrite()` for own-write suppression. Note: dirty detection is document-snapshot based, so a drivers-only change is committed with the next document-changing commit.
  Since ADR 0054 (private) follow-ups: `versioning/git-extra-changes.ts` (`hasExtraFileChanges`, `anyFilesIn`) — isomorphic-git `statusMatrix` scoped to `falang/config` and `falang/drivers` (the directories `git-stage.ts` stages besides documents; any row but `[1,1,1]` is a change, an empty/missing directory never is); `GitVersionStore.commit` also commits when only those files changed, and it implements `hasExtraChanges` (both desktop apps expose it as the `versioning:has-extra-changes` IPC).
- `project-converter` — `@falang/desktop-project-converter`: plain Node (no Electron dependency) migrator from the old (pre-monorepo) desktop app's on-disk format (`project.falangproject.json`, `schemeVersion` 2) into the current v5 `project-fs` format (scheme names and folder structure preserved as on-disk file/directory names) — `isOldFormatProject`/`convertOldProject`, backing up only the falang-owned entries (`project.falangproject.json` + `falang/`) into `<projectDir>/backup/` first; every non-falang entry (the user's own `code/`, README, `.git`, …) stays untouched at the project root throughout, and rollback on a failed conversion restores exactly those two backed-up entries without touching anything else. Since ADR 0035 (private): the old (pre-monorepo) app had no rule against a node's `children[0]` carrying an `out`, so `convertStatement` (`convert-common.ts`) now returns `INode[]` (an `if` conversion can emit one extra, hoisted statement) and three mechanisms fix up what the old tree can't carry over as-is — `fixIfFirstBranchOut` (swap the two branches and invert `meta.trueOnRight` when only one has an out; when both do, hoist slot 0's out into a plain trailing statement right after the `if`, safe because slot 1 unconditionally exits anyway), `rotateFirstParallelThreadIfOut` (rotate a first `parallel-thread` with an out to the end — threads run independently, so order doesn't matter), and `fixFirstStatementOut` (a loop that's itself first in some chain: a trailing `continue` is always a no-op and dropped for any loop kind; `pseudo-cycle`'s `break` is also a no-op and its `return`/`throw` are hoisted, since it always runs its body exactly once; `while`/`foreach`/`from-to-cycle` throw a loud, unsupported error instead of guessing, since a loop that may run zero times can't have its exit generically dropped or hoisted). A first `switch-option` with an out also throws (case reordering isn't safe). Verified against the real `TestReturnDefault` fixture (`test-fixtures/conditions/`), whose `if` has both branches unconditionally returning.
